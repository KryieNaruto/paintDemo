> 关闭垂直同步后帧率不再被刷新率锁定（高刷屏实测帧率 > 刷新率或帧间隔波动，人工记录）；
> 重新开启恢复同步。
>
> —— `docs/tasks/detail/调试按钮.md` §D6-3

## 代码侧已具备的可核验前提（无需人工，已由代码审查/单测覆盖）

- `paint-pc/src/app.cpp` 中 `Checkbox("VSync", &m->vsyncOn)` → `glfwSwapInterval(m->vsyncOn ? 1 : 0)`
  接线正确：勾选/取消对应 `glfwSwapInterval(1)` / `glfwSwapInterval(0)`。
- `Performance` 浮层已显示 `FPS: %.1f`（`ImGui::GetIO().Framerate`），可直接读数。
- `Brush / Display` 面板在 VSync 勾选框旁新增文字提示（ON/OFF 期望现象）及
  **显示器标称刷新率**（`glfwGetVideoMode` 读取），方便测试者对照判断，无需另外用外部工具
  查刷新率。
- SDK 侧纯离屏、无 swapchain/present，`vsync` 概念完全归属消费端 GLFW present 模式切换，
  SDK 侧行为不受影响（该点已由 host ctest 全绿 + sanitize 零泄漏核实，见任务提交记录）。

上述均为**代码正确性**的间接证据，**不能替代**「真实物理显示器上帧率数值随 vsync 开关变化」
这一行为学观测——这正是本文档要人工补齐的部分。

## 测试步骤（供人工测试者参照）

1. 准备一台刷新率明显高于常见桌面默认值的显示器（例如 120Hz / 144Hz / 165Hz），并确认操作系统
   显示设置里该刷新率已生效（避免系统层面把刷新率钳制在 60Hz）。
2. 编译并运行 `paint-pc`（`fix/d6-3-color-vsync` 分支 / 或合并后的目标分支）。
3. 打开后确认左上角 `Performance` 浮层可见（显示 `FPS: xx.x`），以及 `Brush / Display` 面板
   可见（显示 `VSync` 勾选框 + `Monitor refresh rate (nominal): NNN Hz`）。
4. **VSync = ON**（默认勾选状态）：
   - 静置几秒待 FPS 读数稳定，记录 `FPS` 数值。
   - 预期：FPS 应稳定在 `Monitor refresh rate` 附近（允许小幅误差，例如 ±2~3）。
5. 取消勾选 **VSync（切换为 OFF）**：
   - 静置几秒待 FPS 读数稳定/观察，记录 `FPS` 数值（如有明显抖动，记录抖动范围，如
     "在 180~400 之间跳动"）。
   - 预期：FPS 明显偏离步骤 4 的读数（通常远高于刷新率，因为不再被 present 阻塞），或者
     虽然数值接近但帧间隔（`Frame: %.2f ms`）出现可观察的波动（不再是稳定的
     `1000/刷新率` ms）。
6. 重新勾选 **VSync（切换回 ON）**：
   - 静置几秒，记录 FPS 是否恢复到与步骤 4 一致（在合理误差范围内）。
7. 记录测试环境信息（显示器型号/接口、GPU、操作系统、驱动版本如已知）、测试人员、测试时间。
