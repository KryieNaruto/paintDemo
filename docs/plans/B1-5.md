# B1-5 · 白盒移植 Ink Stroke Modeler → `core/stroke_predictor` + host 单测

> - 任务线：`docs/tasks/任务线.md` 第 34 行（线1-预测）
> - 依赖：B1-1（已完成，`core/types.h` 的 `StrokePoint` 已含 `is_predicted` 字段，无扩类型需求）
> - 可并行：B1-3（engine）/ B1-4（C API）均已落地，本任务不依赖它们的预测接线，仅消费其内部类型
> - 状态：计划

---

## 目标

把 Google `ink-stroke-modeler` 的平滑预测算法**白盒移植**进 SDK 内核 `core/stroke_predictor`（跨平台纯 C++，不依赖任何 Android-only 输入管线，不引入 Abseil 依赖），对外不暴露任何新 C ABI 类型。预测点带 `is_predicted` 标记，真实点到达时覆盖预测点。

具体：

1. **`core/stroke_predictor.{h,cpp}`（内部，不对外）**：`StrokeModeler` 类（镜像 `ink_stroke_modeler::StrokeModeler` 的 API），白盒移植 §4.6 四模块——`WobbleSmoother`（低通滤波 → 时间变权移动平均）、`SamplingParams` 重采样（固定 `min_output_rate` 上采样）、`PositionModeler`（弹簧质点 + 固定步长欧拉积分）、`KalmanPredictor`/`StrokeEndPredictor`（绘画场景预测）。Abseil `StatusOr` → C++20 轻量 `Result<T>`（`std::expected` 需 C++23，本仓库 `CMAKE_CXX_STANDARD 20`）。
2. **输入/输出**：复用 `core/types.h` 的 `StrokePoint`（已含 `t_us`/`is_predicted`）。`Update(raw)` 产出平滑真实点（`is_predicted=false`），`Predict()` 外推出预测点（`is_predicted=true`）。
3. **确定性**：固定步长欧拉积分、**无随机**（不吃 RNG）；时间源只读 `StrokePoint.t_us`（B1-7 `FixedTimeStepper` 已在 C API 侧填好），不调用 `std::chrono`/`steady_clock`。
4. **host 单测**：`tests/test_stroke_predictor.cpp` 直接测 `StrokeModeler`，覆盖验收 5 条。
5. **engine 接线（设计 + 默认 passthrough）**：给出预测点流入三线程引擎的接线设计；B1-5 落地用**恒等 passthrough 预测器**（`Update` 原样透传、`Predict` 空），保证既有 engine/CLI/确定性测试零扰动，真实 `StrokeModeler` 只经单测覆盖。

非目标：不实现 GPU 重合成（真实点覆盖是渲染/composite 层职责，归 B2/B3）；不改 `ui/` `platform/` `app/`（无消费者代码）；不改 `IPaintKernel`/`IRenderBackend` 接口签名；不改 C ABI（`dgcStrokeTo` 的 `isPredicted` 参数 B1-4 已冻结）。

## `core/stroke_predictor` 结构

```
core/
├── stroke_predictor.h     # StrokeModelParams + StrokeModeler（Update/Predict/Reset/Configure）
└── stroke_predictor.cpp   # 实现；WobbleSmoother/PositionModeler/Kalman/StrokeEnd/Resampler
                           # 作为内部组件（匿名命名空间或内部 struct），Result<T> 也在 .h
```

### 对外类（SDK 内部，不进入 C ABI）

```cpp
// core/stroke_predictor.h
#pragma once
#include <vector>
#include "core/types.h"           // StrokePoint（已含 is_predicted）

// 调参集合（镜像 SamplingParams + StrokeModelParams 的绘画场景子集）
struct StrokeModelParams {
    // wobble smoothing
    float wobble_timeout_ms      = 40.0f;
    float wobble_speed_floor     = 1.31f;
    // 重采样
    float min_output_rate_hz     = 180.0f;   // 固定 min_output_rate
    float end_of_stroke_stopping_distance_mm = 0.1f;
    // 弹簧质点（位置模型）
    float spring_mass_constant   = 1.0f;
    float spring_drag_constant   = 20.0f;
    // Kalman 预测
    float kalman_process_noise   = 0.0005f;
    float kalman_measurement_noise = 0.004f;
    float prediction_interval_ms = 16.0f;    // 外推时长
};

// 轻量 Result<T>（Abseil StatusOr 的 C++20 替代；value + ok，无异常跨 C ABI）
template <typename T> struct Result { T value; bool ok; };

class StrokeModeler {
public:
    StrokeModeler();
    ~StrokeModeler();
    StrokeModeler(const StrokeModeler&) = delete;
    StrokeModeler& operator=(const StrokeModeler&) = delete;

    void Configure(const StrokeModelParams&);   // 调参（可选，缺省用上表默认）
    void Reset();                                // 清空内部缓冲/弹簧/Kalman 状态

    // 输入一个原始真实点（is_predicted=false），追加平滑后的真实点到 out（is_predicted=false）。
    // 内部丢弃被真实点覆盖的预测点（覆盖语义见下）。
    void Update(const StrokePoint& raw, std::vector<StrokePoint>* out);

    // 外推未来点，追加预测点到 out（is_predicted=true）。
    void Predict(std::vector<StrokePoint>* out);

private:
    struct Impl;                       // Pimpl：内部组件与状态全藏在 .cpp
    std::unique_ptr<Impl> impl_;       // RAII 持有，无裸 new/delete
};
```

### 覆盖语义（验收 3 的可断言载体）

- 每次 `Update` 以**真实输入**为准重做平滑，并**清空**上一轮 `Predict` 挂起的预测点缓冲，使「预测点在前、真实点在后」的流水里，真实点到达即替换（覆盖）同段预测点——输出流里不会出现「同一时刻既有预测点又有真实点」的重复。
- 单测可直接断言：`Predict` 产出的预测点（`is_predicted=true`）总在最后一个真实点之后（`t_us` 更大 / 沿速度方向外推）；随后 `Update` 下一真实点后，该预测点不再出现在输出中（被覆盖），真实点 `is_predicted=false`。
- 真正的像素级「重合成覆盖」（预测 stamp 被真实 stamp 重合成）在渲染/composite 层，**不属本任务**（见验收 5）。

## 与 engine 的接线（预测点如何流入）

### 目标流（设计）

```
外部(C API 线程) --dgcStrokeTo(raw, isPredicted=0)--> submitInput(StrokeEvent{StrokePoint})
    --> 输入线程 pending_input_ --> [StrokeModeler 预测] --> input_to_brush_(SPSC)
    --> 内核线程 kernel_->strokeTo(p, is_predicted)  // 预测点与真实点同管线
    --> 渲染线程 composite/present                    // 预测 stamp 被真实 stamp 重合成（B2/B3）
```

- 预测在**输入线程**（`Engine::inputLoop` 内，`pending_input_` 取出后、`try_push` 进 `input_to_brush_` 之前）执行：对真实 `StrokePoint` 事件调 `Update(raw, &out)` 产出平滑真实点，再调 `Predict(&out)` 外推预测点；把 `out` 里的每个点都包成 `StrokeEvent{StrokePoint, is_predicted}` 依次 `try_push`。
- `BeginStroke` 事件触发 `Reset()`；`EndStroke` 事件触发 `Reset()`（清态）。
- 预测点与真实点共用 `is_predicted` 字段（`StrokePoint` 已含），经同一条 SPSC 到内核线程，内核按 `is_predicted` 给 stamp 打标；渲染层据此做覆盖（后续任务）。

### B1-5 落地取向：默认 passthrough，真实 `StrokeModeler` 只经单测

- 为避免扰动既有测试（B1-3 `test_engine`、B5-2 `test_cli`、B1-7 `test_determinism` 均依赖当前「点原样流转」行为），本任务**不把真实 `StrokeModeler` 接进 `Engine::inputLoop`**，而是：

  1. 在 `Engine` 增加一个**可注入预测器槽**（`std::unique_ptr<StrokeModeler>`，RAII，默认 `nullptr` 表示 passthrough）。`inputLoop` 内当槽非空时才走 `Update/Predict`，否则维持现有「原样透传」。
  2. B1-5 交付时该槽默认**保持 nullptr**（行为不变）；真实接线属 B2/B3（真实内核落地）时的增量改动，届时补「预测点流入 + 覆盖」的引擎级断言。

- 这样既给出「预测点如何流入」的明确接线设计，又不破坏当前 engine/CLI/确定性回归绿。

> 取舍理由：B1-5 验收 5 条全部落在 `StrokeModeler` 行为上（`Update`/`Predict`/覆盖/确定性/不实现 GPU 重合成），无一要求「engine 内观察到预测」。把真实预测接进 engine 会引入「预测点与真实点时序」「CLI golden 像素」等超出本任务的回归面，故接线仅做设计预留 + passthrough 默认。

## 所有权设计 / Pimpl 边界 / 泄漏验证（SDK 工程约束）

### 所有权（RAII，零裸 new/delete）

```
StrokeModeler（core/ 内部，非 C ABI）
  └─ std::unique_ptr<Impl> impl_          // 唯一堆所有权令牌
       └─ Impl（定义在 stroke_predictor.cpp）
            ├─ WobbleSmoother      wobble_;      // 值成员（含 std::vector 缓冲）
            ├─ PositionModeler     position_;    // 值成员（弹簧状态：位置/速度标量）
            ├─ KalmanPredictor     kalman_;      // 值成员（协方差矩阵等）
            ├─ StrokeEndPredictor  end_pred_;    // 值成员
            ├─ std::vector<StrokePoint> pending_predicted_;  // 预测点缓冲（覆盖语义载体）
            └─ StrokeModelParams   params_;      // 值成员
```

- 所有子组件为**值成员**（内部 `std::vector`/`std::array`/标量），无指针所有权；唯一 `unique_ptr` 是 `StrokeModeler::impl_`（经典 Pimpl，隐藏实现于 .cpp）。
- 无裸 `new`/`delete`；不提供拷贝构造/赋值（`= delete`），`StrokeModeler` 为不可拷贝、可移动（如需要）。
- `StrokeModeler` 自身在 SDK 内由 `DgcContext::Impl`（`sdk_api/dgc_paint_c_api.cpp`）或 `Engine` 以 `std::unique_ptr` 持有（若接线），绝不裸指针交接所有权。

### Pimpl 边界

- `core/stroke_predictor.h` 是**内部头**（`target_include_directories(dgc_paint PRIVATE ${CMAKE_CURRENT_SOURCE_DIR})` 已覆盖，见 `CMakeLists.txt:56-58`），**不加入** PUBLIC include（PUBLIC 仍只有 `sdk_api/`）。
- `StrokeModeler`/`StrokeModelParams`/`Result<T>` **不进入 C ABI**：`sdk_api/dgc_paint_c_api.h` 一字不改，唯一不透明句柄仍是 `typedef struct DgcContext DgcContext;`。
- 预测能力若日后经 C API 暴露，走既有的 `dgcStrokeTo(..., isPredicted)` 标志（B1-4 已冻结），**不新增句柄类型**。

### 泄漏验证方式

- **静态**：`grep -rnE '\bnew\b|\bdelete\b' --include='*.h' --include='*.cpp' core sdk_api render`，非 `third_party` 仅剩 `= delete`（删拷贝），无 `new X`/`delete x` 所有权表达式。
- **动态（ASan/LSan）**：`-DDGCPAIN_SANITIZE=ON`（`CMakeLists.txt:26-35` 已接 ASan+LSan）构建跑 `ctest`，重点 `test_stroke_predictor`（`StrokeModeler` 构造/析构多轮 + `Update/Predict` 产生 `std::vector` 输出，覆盖 `impl_` 与内部 `std::vector` 释放路径）；LSan 零报告。
- **压力**：单测内循环 `make_unique<StrokeModeler>` → `Update`/`Predict` → 析构 N 轮，进程退出 LSan 汇总零泄漏。

## 步骤

### 1. `core/stroke_predictor.h`（内部头）

按上面「结构」节落 `StrokeModelParams` / `Result<T>` / `StrokeModeler` 声明。要点：

- `Result<T>`：`template <typename T> struct Result { T value; bool ok = false; };`（C++20，替代 `absl::StatusOr`，不引入 `std::expected`）。
- `StrokeModeler` 用经典 Pimpl：`std::unique_ptr<Impl> impl_;`，析构在 .cpp（`Impl` 完整后）定义。

### 2. `core/stroke_predictor.cpp`（白盒移植四模块）

按 §4.6 移植顺序（每一块先用最小可测实现立住，再调参）：

1. **WobbleSmoother**：输入点做低通滤波 → 时间变权移动平均；输出抖动方差显著低于原始点流。
2. **Resampler**：按 `min_output_rate_hz` 固定上采样，保证输出点密度下限；`min_output_rate` 越大点越密。
3. **PositionModeler**：弹簧质点模型，`spring_mass_constant`/`spring_drag_constant` 控制响应；用**固定步长欧拉积分**（步长取点间 `Δt = (t_us[i+1]-t_us[i])/1000` 或固定微步，**不读真实时钟**）。
4. **KalmanPredictor** / **StrokeEndPredictor**：`Predict()` 沿速度方向外推，产 `is_predicted=true` 点；`Update()` 时用真实点更新状态并清空挂起预测（覆盖语义）。

> 每块保持纯函数式（输入 `StrokePoint`/标量 → 输出标量/`StrokePoint`），便于 host 单测逐块断言。

## 测试方案（host 单测 + 验收逐条映射）

| 验收（任务书原文） | 单测用例 | 断言 |
|---|---|---|
| 1. `Update` 输入原始点流 → 平滑后点流 | `Update` 平滑：喂一条带抖动的直线（正弦 wobble 叠加），收集平滑输出 | 输出全 `is_predicted=false`；输出抖动方差 < 输入抖动方差（低通生效）；点未被吞（非空） |
| 2. `Predict` 产出预测点带 `isPredicted` 标记 | `Predict` 预测：若干 `Update` 后调 `Predict()` | 输出非空且**全部** `is_predicted=true`；预测点 `t_us` 大于最后真实点 `t_us`（沿外推方向） |
| 3. 真实点覆盖关系可断言 | 覆盖：`Predict` 产出预测点后，`Update` 下一真实点 | 预测点不再出现在后续输出（被覆盖）；真实点 `is_predicted=false`；同一 `t_us` 不出现「预测+真实」重复 |
| 4. 固定步长欧拉积分（无随机）确定性可测 | 确定性：同一输入点流喂两个全新 `StrokeModeler` 实例 | 两实例输出逐点（x/y/pressure/tilt/t_us/is_predicted）完全相等（byte/float 相等）；不依赖任何 RNG |
| 5. 不实现 GPU 重合成 | 负向验证：本任务产物无 render/composite 改动 | `git diff --stat` 不含 `render/` 改动；`core/stroke_predictor.*` 不 include 任何 `render/`/Vulkan 头；`grep -r "composite\|vk"` 命中为空 |

附加（工程约束）：

- **泄漏循环**：`for (N 轮) { auto m = std::make_unique<StrokeModeler>(); m->Update(...); m->Predict(...); }`，`DGCPAIN_SANITIZE=ON` 下 LSan 零报告。
- **回归**：既有 8 个 ctest（`compile_null`/`test_ring_buffer`/`test_engine`/`test_c_api_header`/`test_c_api_b1_6`/`test_offscreen`/`test_ownership_loop`/`test_determinism`）全绿——因预测器默认 passthrough，无行为扰动。
- **C ABI 头冻结**：`test_c_api_header`（纯 C 解析）继续通过，`sdk_api/dgc_paint_c_api.h` 零 diff。

## 风险与备选

1. **算法保真度（白盒移植 vs oracle）**：白盒重写若细节（积分步长、滤波窗口、Kalman 初值）与 `ink-stroke-modeler` 有浮点偏差，手写/绘画手感可能不符。缓解：固定步长欧拉 + 无随机 + 确定性测试向量，使输出可复现；后续路线 E「host oracle 对照测试框架」（规划 §4.6/§路线整理 866）用 `ReplayRandom` 回放 oracle dab 序列做逐位 diff，本任务先保证**确定性**与**结构正确**，不做像素级手感标定。
2. **Abseil 替代（C++20）**：`std::expected` 需 C++23，本仓库 `CMAKE_CXX_STANDARD 20` 不可用。备选：a) 自研 `Result<T>`（推荐，value+ok）；b) 直接 `std::optional<T>` + 错误分支用 `bool` 返回。取 a，避免可选值语义二义。
3. **时间源依赖**：移植过程若误用 `std::chrono::steady_clock` 会破坏确定性并引入平台差异。缓解：`StrokeModeler` 只读 `StrokePoint.t_us`（B1-7 `FixedTimeStepper` 已在 C API 侧填入固定步进值），代码评审 + 单测 4 的确定性断言兜底；`grep` 检查 `core/stroke_predictor.*` 无 `chrono`/`steady_clock`/`system_clock`。
4. **engine 接线范围蔓延**：把真实预测接进 `Engine::inputLoop` 会引入「预测点与真实点时序」「CLI golden 像素」「测试回归」三方面超出本任务的复杂度。缓解：默认 passthrough（槽 `nullptr`），真实接线推至 B2/B3 真实内核落地时，且届时补引擎级断言。
5. **覆盖语义与渲染解耦**：验收 3「真实点覆盖关系可断言」在**预测器输出流层面**断言（预测点被真实点替换、无重复），而非像素级重合成。真正的「预测 stamp 被真实 stamp 重合成覆盖」在渲染/composite 层，属 B2/B3（GPU 重合成），本任务明确不做（验收 5）。执行时若审方要求像素级覆盖，需上浮到 B2/B3，不属 B1-5。
6. **并行依赖无关性**：B1-5 只依赖 B1-1（`StrokePoint` 类型已含 `is_predicted`），与 B1-3/B1-4 的 engine/C API 已完成状态无冲突；本任务不修改 `core/types.h`，故不牵连 B1-3/B1-4 的既有编译。
