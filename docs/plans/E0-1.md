## 步骤

全部在 worktree 内完成。Windows 上用 `python`；脚本本身是 bash，实现阶段用 Git Bash / WSL 写和试跑。

### 1. 写 `docs/env/toolchain.md`（版本下限 SOT）

写清三档，数字与脚本顶部常量相同：

**必需（缺 → 非零）**

- CMake ≥ **3.22**（`cmake --version` 主.次比较）
- Ninja（`ninja`；部分发行版命令名为 `ninja-build`）
- C++ 编译器：若已设 `CXX` 则用之，否则依次试 `g++` / `clang++` / `cl`

**有则探测、无则警告（仍 0 退出）**

- `ANDROID_NDK_HOME`（可兼容同族 `ANDROID_NDK`）；有则打印 `source.properties` 的 `Pkg.Revision`
- 文档可写规划建议 NDK r27+（建议 r28），**脚本不因版本偏低而失败**
- Vulkan 头或 `libvulkan`：`pkg-config vulkan`，或常见路径 `vulkan/vulkan.h`，或环境变量 `VULKAN_SDK`

**非失败项（不要当成门禁）**

- GLFW / JDK / Android Studio：打印「消费者侧，见 `docs/git/`」，**不因缺失失败**
- 不必 `command -v glfw` / `java`；即使去查，也不得把缺失设为 FAIL

写明：安装步骤归 E0-2（Linux apt）、E0-3（NDK）、E0-4（VS2026）；本文件只定义「探测什么、退出码是什么」。

建议退出码表（写入文档，脚本遵守）：

| 码 | 含义 |
|---|---|
| 0 | 必需项齐（NDK/Vulkan 可仅 WARN） |
| 1 | 缺 cmake / cmake &lt; 3.22 / 缺 ninja / 缺 C++ 编译器 |

### 2. 写 `scripts/check-env.sh`

风格对齐 `bootstrap-consumer.sh`：`#!/usr/bin/env bash`、仓库根相对路径、`--help`、中文说明。

**定位仓库根**：以脚本自身目录上一级为 SDK 根（`dirname "$0"/..`），不依赖调用时 cwd。在仓库根打印一条 `SDK root: ...`。

**控制流（避免 `set -e` 把可选探测打成失败）**

- 不要照搬 `set -euo pipefail` 到可选探测。建议 `set -u`，用 `REQUIRED_FAIL=0` 汇总；可选探测包在 `if` / `|| true` 里。
- 每项一行：`OK` / `WARN` / `FAIL` + 工具名 + 版本或路径。
- 全部必需项通过 → `exit 0`（即使有 NDK/Vulkan WARN）。
- 任一必需项失败 → `exit 1`。

**CMake**

- 解析 `cmake --version` 第一行的主.次版本，与 `3.22` 比较（须兼容 3.31、**4.x**，不要写死只认 `3.x`）。
- 无 cmake，或有但 &lt; 3.22：与「缺 cmake」同等，**非零退出**。

**Ninja**

- `command -v ninja`；若无则试 `ninja-build`。缺则 **FAIL / 非零**（探测规则表：ninja 与 cmake/C++ 同档，不只验收三条里的 cmake/C++）。

**C++**

- 能找到编译器且能跑 `--version`（MSVC `cl` 能被 `command -v` 到即可）即通过。
- **不要**编译测试 `.cpp`（尚无工程 `CMakeLists.txt`）。

**NDK**

- 只读 `ANDROID_NDK_HOME`，未设再看 `ANDROID_NDK`。**不要**扫整盘，也不要枚举 `ANDROID_SDK_ROOT/ndk/*` 当成功条件（任务书写的是 `ANDROID_NDK_HOME` / NDK）。
- 目录存在：打印 `Pkg.Revision`；无 `source.properties` 则打印路径 + WARN（仍不算必需失败）。
- 未配置：`WARN`「NDK 未配置，host 可先编」→ **仍 0**（前提是必需项都过）。

**Vulkan**

- 有：打印头或库来源（`pkg-config`、`VULKAN_SDK/Include`、常见 `/usr/include/vulkan/vulkan.h` 等）。
- 无：`WARN`（Null 后端不需要；L4 才硬依赖）→ 不改变退出码。

**GLFW / JDK / Studio**

- 固定一行 INFO：属 `paint-android` / `paint-pc` 消费者，见 `docs/git/`。**不要**把「找不到 java/glfw」设为 FAIL。

**不要**

- `sudo apt install …`（E0-2）
- 调用 `cmake -S` / `--build` / 生成 presets
- 创建 `CMakeLists.txt`、`CMakePresets.json`、`ui/`、`platform/`、`app/`
- 另交 `.ps1` 作为本任务交付（任务书产出是 `check-env.sh`）

**可执行位（Windows worktree）**

- 提交时保持 `100755`。若 `chmod +x` 在 NTFS 上无效，用 `git update-index --chmod=+x scripts/check-env.sh`。

- 把「探测脚本见任务 E0-1」改成链到 `scripts/check-env.sh` 与 [`docs/env/toolchain.md`](docs/env/toolchain.md)。

### 4. 自检（留给 execute / test；本阶段不跑满）

在 **bash**（Linux，或本机 Git Bash / WSL）下，于 **worktree 根**执行：

1. 正常 PATH：脚本能跑完。本机若无 NDK，必须出现 NDK `WARN` 且 **exit 0**（若 cmake/ninja/C++ 已齐）。
2. PATH 去掉 `cmake`（或临时函数让 `cmake` 返回 127）：**非零**。
3. 隐藏 C++ 编译器（清 `CXX`，PATH 不含 `g++`/`clang++`/`cl`）：**非零**。
4. `env -u ANDROID_NDK_HOME -u ANDROID_NDK`：有 WARN，不单独导致失败。
5. git diff **没有** 仓库根 `CMakeLists.txt`，没有 `ui/` `platform/` `app/`。

Windows 无 bash 时：test 阶段用 Git Bash；不要把「本机装齐 VS2026」当成本任务验收（那是 E0-4）。

## 风险

| 风险 | 处理 |
|---|---|
| `set -e` + `command -v` / `pkg-config` 失败直接退出 | 可选探测不依赖 errexit；必需项失败汇总后统一 `exit 1` |
| CMake 4.x 版本解析失败被当成 &lt; 3.22 | 按主.次数字比较，不要写死 `3.x` 正则 |
| 本机是 Windows，验收句写的是 Linux | 脚本保持 POSIX bash；用 PATH 隔离模拟「缺 cmake / 缺编译器 / 缺 NDK」；不把 VS 安装当验收 |
| 把 ninja 做成 WARN | 探测规则表：ninja 与 cmake/C++ 同档，缺则非零 |
| 把 NDK 做成硬失败 | 违反验收；默认 0 + WARN |
| 探测 GLFW/java 失败就 `exit 1` | 违反「不因无 GLFW 失败」；只打印消费者提示 |
| 顺手加 `CMakeLists.txt` 方便本地试编译 | **禁止**；归 B1-2 |
| 文档与脚本下限不一致 | 数字只写在 `docs/env/toolchain.md` + 脚本顶部常量，README 引用 |
| Windows 提交后脚本无执行位 | `git update-index --chmod=+x` |
| 扫 SDK Manager 多版本 NDK 当「已配置」 | 只认 `ANDROID_NDK_HOME` / `ANDROID_NDK`，避免误报 |

无需要人拍板的分叉：产出形态（README + `docs/env/`）由任务书「或」覆盖；脚本语言由任务书定为 `check-env.sh`。
