## 设计

### 1. `core/ring_buffer.h` —— 无锁 SPSC 环形队列（header-only）

任务书产出只列 `core/ring_buffer.h`（无 `.cpp`），采用 header-only 模板，避免与 §7.7 示例里的 `core/ring_buffer.cpp` 冲突（见「风险」）。

```cpp
#pragma once
#include <atomic>
#include <array>
#include <cstddef>
#include <cassert>

// 无锁 SPSC 环形队列：单生产者 + 单消费者，满/空/环绕语义由单调计数器推导。
// Capacity 必须是 2 的幂。
template <typename T, std::size_t Capacity>
class RingBuffer {
public:
    static_assert((Capacity & (Capacity - 1)) == 0, "Capacity must be power of two");

    bool try_push(const T& v);   // 满返回 false
    bool try_pop(T& out);        // 空返回 false
    bool empty() const noexcept; // tail == head
    bool full()  const noexcept; // tail - head == Capacity
    std::size_t size() const noexcept;
    void clear() noexcept;       // 仅供单线程复位，非并发安全

private:
    std::array<T, Capacity> buf_{};
    std::atomic<std::size_t> head_{0}; // 消费者
    std::atomic<std::size_t> tail_{0}; // 生产者
};
```

要点：
- 用**单调递增计数器** `head_` / `tail_`（不依赖实际回绕），下标 = `idx % Capacity`；`empty()` = `tail == head`，`full()` = `tail - head == Capacity`。这样「环绕」（push/pop 累计超过 Capacity）是自然行为，单测可直接验证。
- 内存序：生产者在写入 slot 后 `tail_.store(..., release)`；消费者 `head_.load(..., acquire)` 读 slot，消费后 `head_.store(..., release)`。SPSC 下 `try_push` / `try_pop` 无锁、无 CAS。
- `clear()` 仅用于单线程场景（如 engine stop 后复位），不承诺并发安全，并在注释标明。
- 模板存放 `std::array<T, Capacity>`，要求 `T` 可默认构造；`StampData` 的批处理用 `std::vector<StampData>` 作为元素（见 engine），均满足。

### 2. `core/engine.h/.cpp` —— 三线程编排

```cpp
// core/engine.h
#pragma once
#include <atomic>
#include <thread>
#include <vector>
#include "core/ring_buffer.h"
#include "core/types.h"

class IPaintKernel;
class IRenderBackend;

enum class StrokeEventType { BeginStroke, StrokePoint, EndStroke };
struct StrokeEvent { StrokeEventType type; StrokePoint point; };

class Engine {
public:
    Engine(IPaintKernel* kernel, IRenderBackend* backend); // 注入，不拥有
    ~Engine();                                            // 保证 stop()
    Engine(const Engine&) = delete;
    Engine& operator=(const Engine&) = delete;

    void start();                 // 幂等：已启动则直接返回
    void stop();                  // 幂等：置停标志 → 唤醒 → join 三线程，不卡死
    bool running() const noexcept;

    // 外部（C API / 平台线程）入队口：B1-4 从这里接。
    bool submitInput(const StrokeEvent& ev); // 满则返回 false（调用方可重试/丢弃）

private:
    void inputLoop();             // 输入线程：外部队列 → input_to_brush
    void brushLoop();             // 内核线程：strokeTo → stamp 批 → brush_to_render
    void renderLoop();            // 渲染线程：composite + present

    IPaintKernel*  kernel_;
    IRenderBackend* backend_;

    // 两段无锁 SPSC 队列
    RingBuffer<StrokeEvent, 1024>          input_to_brush_;
    RingBuffer<std::vector<StampData>, 256> brush_to_render_;

    // 外部入队边界（线程安全，来自 UI/C API 线程）
    std::deque<StrokeEvent> pending_input_;        // 需 <deque>
    std::mutex              input_mutex_;          // 需 <mutex>
    std::condition_variable input_cv_;             // 需 <condition_variable>

    std::atomic<bool> stop_{false};
    std::thread input_thread_;
    std::thread brush_thread_;
    std::thread render_thread_;
};
```

要点（线程与数据流，对齐 §4.7）：

| 线程 | 职责 | 同步 |
|---|---|---|
| Input Thread | 从 `pending_input_`（mutex + condvar）取 `StrokeEvent` → push 进 `input_to_brush_` | `std::condition_variable` + SPSC ring |
| Brush Thread | 从 `input_to_brush_` 取事件 → `kernel_->beginStroke/strokeTo/endStroke` → `std::vector<StampData>` 批 → push 进 `brush_to_render_` | 两段 SPSC ring |
| Render Thread | 从 `brush_to_render_` 取 stamp 批 → `backend_->composite(batch)` → `backend_->present()` | SPSC ring |

- **输入线程存在的理由**：外部（C API）从任意线程调 `submitInput`，先落线程安全的 `pending_input_`，由输入线程搬到无锁 SPSC 段——保证 `input_to_brush_` 仍是「单生产者（输入线程）× 单消费者（内核线程）」，SPSC 约束成立。
- **阻塞 push 辅助**：每段 SPSC 消费者侧都用「`while(!stop_ && !try_push(...)) std::this_thread::yield();`」式的有界等待，配合 `stop_` 检查，任何时刻 stop() 都能让三线程在若干次 yield 内退出，规避满队列死锁。
- **stop() 顺序**：`stop_ = true` → `input_cv_.notify_all()`（唤醒输入线程）→ 依次 `join` 三个线程。消费循环每轮先判 `stop_`，保证立即退出。
- **不改接口为 GPU command**：引擎只调用 B1-1 已定义的 `strokeTo` / `composite` / `present` 等既有纯虚方法，不新增/改动 `IPaintKernel` / `IRenderBackend` 的任何方法；渲染线程不接触 Vulkan/GPU 资源概念。

### 4. 单测

- `tests/test_ring_buffer.cpp`：用 `RingBuffer<int, 8>`（2 的幂）逐项断言——
  - 空：初始 `empty()==true`、`try_pop` 返回 false。
  - 满：连续 `try_push` 8 次成功、第 9 次返回 false、`full()==true`、`size()==8`。
  - 环绕：push/pop 交替累计远超 Capacity（如 100 次「push 3 + pop 3」），断言 FIFO 顺序正确、下标越过 Capacity 仍正确回绕、不丢不重。
- `tests/test_engine.cpp`：实例化 `NullPaintKernel` / `NullRenderBackend` → `Engine e(&kernel, &backend)` → `e.start()` → `submitInput` 若干事件（Begin/Point×N/End）→ 短暂 `sleep_for` 让三线程消化 → `e.stop()`；用 `std::chrono` 计时断言 stop() 在时限内（如 < 2s）返回、`running()==false`，并断言 `start()` 幂等（重复 start 不崩）。

## 风险

- **ring_buffer 的 `.cpp` 口径**：任务书产出写 `core/ring_buffer.h`（无 `.cpp`），而 `路线整理.md` §7.7 示例列出 `core/ring_buffer.cpp`。本计划以任务书为准做成 header-only 模板；若后续评审要求 `.cpp`，再显式实例化特化或改非模板，不影响本次验收（满/空/环绕单测照常）。
- **三线程里输入线程的定位**：§4.7 只给「Input/Brush/Render + SPSC」一句话，未规定外部入口落到哪。本计划让 `submitInput` 先落 mutex 队列、由输入线程搬进 SPSC 段，保证 SPSC 单生产者约束成立；若评审倾向「外部直接 `try_push` 进 SPSC、去掉输入线程」，只需把 `submitInput` 改为直写 `input_to_brush_`，engine 减一线程，接口与单测不变。
- **stop() 不卡死的保证**：SPSC 消费侧全用「yield + `stop_` 检查」的有界等待，无裸忙等；输入线程由 condvar 唤醒。若未来改成真正 blocking pop，需用带谓词的 `wait` 或 semaphore，否则 stop() 可能挂起——本计划明确规避。
- **begin/end 走内核线程**：`IPaintKernel::beginStroke/endStroke` 有状态，必须在内核线程执行，故输入队列元素是 `StrokeEvent`（含 Begin/Point/End）而非裸 `StrokePoint`。B1-4 的 `dgcBeginStroke/dgcStrokeTo/dgcEndStroke` 直接映射到 `submitInput` 的三种事件。
- **render 线程 present 频次**：本任务 Null 后端 present 为空操作，render 线程按 stamp 批 `composite` + `present`；`beginFrame`/`clearCanvas`/`resize` 的帧节流与 C API 编排归 B1-4，本任务不引入帧率/双缓冲逻辑。
- **越界**：不得改 `core/interfaces/*`（即「不改接口为 GPU command」）、不得写 `sdk_api/dgc_paint_c_api.h`（B1-4）、不得建 `ui/ platform/ app/`、不得引入真实 GPU/GLFW。
