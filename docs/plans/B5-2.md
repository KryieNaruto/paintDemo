## 目标

把 `cli/dgc_cli` 做成 **SDK C API 的第一个 host-only 宿主**，一次性解释执行 JSON 批处理脚本，走 `dgcSetOffscreenSurface → ops → dgcExportPNG` 离屏链路产出 PNG（§4.0.6）。CLI **只** `#include "dgc_paint_c_api.h"`，与 Android/PC UI 调同一套 C API（界面↔CLI↔C API 一一对应，§4.0.4）。

具体：

1. **CLI 入口**：`dgc_cli run <script.json> [--out <result.png>]` + `--help`；host-only，不参与 Android 构建。
2. **JSON 批处理脚本解释器**：解析 §4.0.6 脚本结构（`canvas` / `seed` / `fixed-time` / `ops[]`），逐 op 解释执行，覆盖 §4.0.4 全映射。
3. **离屏渲染调用链**：`dgcCreate → dgcSetOffscreenSurface → dgcClear → [seed/fixed-time] → [ops] → dgcFlush → dgcExportPNG → dgcDestroy`，产出真实 PNG。
4. **参数化 setting/color**：`set-param`（string setting → `DgcBrushSetting` 枚举）→ `dgcSetBrushSetting`；`set-color` → `dgcSetBrushColor`。
5. **确定性接线**：`seed` → `dgcSetRandomSeed`；`fixed-time` → `dgcSetFixedTime`（B1-6/B1-7 已接线，CLI 透传）。
6. **补齐同步缺口**：为「enqueue stroke（引擎三线程异步）→ export（同步读回）」加 **flush/drain 屏障**，保证 export 前所有已提交输入已合成（§4.0.3「CLI 离屏同步」语义）。

非目标：不改 `ui/` `platform/` `app/`；不实现真实内核 dab（B3-1）；不做 golden PNG 逐字节 diff（B5-3）；不做 AI 侧像素对比（§4.0.6 明确「对比模式不在 CLI 范围」）；不实现窗口/swapchain `present` 路径（B2-1 离屏 only）。

## 验收标准（人工授权派生，非任务书原文）

依据 §阶段7 四条 + §4.0.6：

1. **CLI 入口**：`dgc_cli run <script.json> [--out <result.png>]` 可执行；`--help` 打印用法；缺脚本路径 / 非法 JSON / 未知 op 时**非零退出**并输出错误到 stderr（§4.0.6）。
2. **离屏 PNG 产出**：`dgc_cli run script.json` 从无到有产出 PNG 文件（离屏 `dgcSetOffscreenSurface → dgcClear → dgcExportPNG`），host 用 lavapipe headless 运行、无需显示服务器、无需 GLFW（§阶段7「test_offscreen」口径）。
3. **§4.0.4 映射全覆盖**：映射表每个 UI 操作都有对应 CLI 命令，且命令调**同一** C API 函数（`canvas`/`load-brush`/`set-brush`/`set-param`/`set-color`/`stroke`/`clear`/`undo`/`export`/`seed`/`fixed-time`），由 `test_cli` 逐条断言（§阶段7「test_cli」）。
4. **确定性接线**：脚本 `seed`/`fixed-time` 透传 `dgcSetRandomSeed`/`dgcSetFixedTime`；两函数返回 `DGC_OK`，不崩溃（同脚本同 seed 像素级一致属 B5-3，本任务只保证接线正确）。
5. **参数化接线**：`set-param` 的 string setting 名映射到 `DgcBrushSetting` 枚举值（`radius`/`hardness`/`opacity`/`radius_logarithmic`），`set-color` 的 RGBA 透传 `dgcSetBrushColor`（§4.0.2/§4.0.6 示例对齐）。
6. **全操作闭环**：`dgc_cli` 可解释执行完整脚本（建画布 → 选笔刷 → 调参 → 选色 → 画笔迹 → 清空 → 撤销 → 导出）**全程不崩溃、正确返回**并产出 PNG；对当前 `NOT_IMPLEMENTED` 的 op（brush 相关/undo）经 `dgcGetLastError` 报告错误并**按策略继续**（best-effort，见 R2），不中止（§阶段7「全操作闭环」）。
7. **所有权 / Pimpl（SDK 约束）**：`dgc_paint` 库内新增代码（`Engine::flush`/`dgcFlush`）零裸 `new`/`delete`；CLI 作为宿主仅 `#include "dgc_paint_c_api.h"`，**不 include `core/`/`render/`/`kernels/` 任何内部头**，`DgcContext*` 经 RAII 包装（`std::unique_ptr` + 自定义 deleter 调 `dgcDestroy`），无裸 `delete`/手动 destroy（§4.0.2 C API 边界 + B1-8 Pimpl 口径）。
8. **泄漏验证**：`DGCPAIN_SANITIZE=ON`（ASan/LSan）下 `ctest` 零报告，`dgc_cli` 进程 create/destroy 配对（`test_cli` 覆盖）。
9. **测试**：新增 `test_cli`（解释器全操作映射 + 离屏产出 PNG），并保留既有 ctest 全绿（`compile_null`/`test_ring_buffer`/`test_engine`/`test_c_api_header`/`test_c_api_b1_6`/`test_offscreen`/`test_ownership_loop`/`test_determinism`）。

## 所有权设计 / Pimpl 边界 / 泄漏验证（SDK 工程约束）

### 所有权（谁拥有、RAII、零裸 new/delete）

- **SDK 库（`dgc_paint`）内改动**（仅 `Engine::flush` 方法 + `dgcFlush` 包装）：不新增任何堆对象所有权，只读/等待既有队列；`dgcFlush` 不持有资源，返回 `int` 错误码。既有 `DgcContext::Impl` 的 `kernel`/`backend`/`engine`/`rng` 全为 `unique_ptr`，B5-2 不改其声明序，析构逆序（engine→backend→kernel→rng）不变。
- **CLI 宿主（`cli/`，不属于 `dgc_paint` 库）**：`DgcContext*` 生命周期用 RAII 守卫包装——`std::unique_ptr<DgcContext, decltype(&dgcDestroy)> ctx(dgcCreate(), &dgcDestroy)`（或等价小类 `CtxGuard`），异常/提前返回均自动 `dgcDestroy`，**禁止裸 `delete`/手动 `dgcDestroy`**。JSON 文档、op 列表、点流缓冲全部 `std::`/`unique_ptr`，无裸 `new`/`delete` 所有权。

### Pimpl 边界（对外 ABI 面经不透明句柄隐藏实现）

- CLI 编译期**只** include `sdk_api/dgc_paint_c_api.h`；链接只链 `dgc_paint`。`DgcContext` 在头内是 `typedef struct DgcContext DgcContext;`（不透明），CLI 无法也不得访问 `Impl`。
- `cli/` 的 CMake 通过 `target_link_libraries(dgc_cli PRIVATE dgc_paint)` + `target_include_directories` 仅指向 `sdk_api/`（不把 `${CMAKE_SOURCE_DIR}` 加进 CLI 的 include，从机制上杜绝 `#include "core/..."` 误用）。
- `dgcFlush` 是纯 C ABI（`extern "C"`，头内仅声明 + 注释），不暴露 `Engine`/`RingBuffer` 等内部类型。

### 泄漏验证方式

- `cmake -DDGCPAIN_SANITIZE=ON --preset host-linux`（或 `-DDGCPAIN_SANITIZE=ON` 追加到 host preset），`add_compile_options(-fsanitize=address,leak)`/`add_link_options` 已是**全局**（顶层 `CMakeLists.txt` 第 25-34 行），`cli/dgc_cli` 与 `tests/` 同受覆盖。
- 跑 `ctest --test-dir build/host-linux --output-on-failure`（含 `test_cli`、`test_ownership_loop`），要求 ASan/LSan **零报告**；`dgc_cli` 进程退出时 `CtxGuard` 已 `dgcDestroy`，验证无 context 泄漏。

### 2. 脚本 schema 与 op 映射（`cli/script_runner.cpp` 核心）

解析 §4.0.6 结构，逐 op 分发到 C API：

| CLI op / 顶层字段 | JSON 字段 | C API（当前返回码） |
|---|---|---|
| `canvas`（顶层） | `{w,h,background:[r,g,b,a]}` | `dgcSetOffscreenSurface(ctx,w,h)` + `dgcClear(ctx,r,g,b,a)` |
| `seed`（顶层，可选） | `"seed": N` | `dgcSetRandomSeed(ctx,N)` |
| `fixed-time`（顶层，可选） | `"fixed-time": T` | `dgcSetFixedTime(ctx,T)` |
| `load-brush` | `{id,path}` | `dgcLoadBrushFromMyb(ctx,path)` → 当前 `NOT_IMPLEMENTED`，记 `id→INVALID_BRUSH` |
| `set-brush` | `{id}` | `dgcSetBrush(ctx, handle[id])` → 当前 `NOT_IMPLEMENTED` |
| `set-color` | `{r,g,b,a}` | `dgcSetBrushColor(ctx, currentBrush, r,g,b,a)` → 无有效 brush 时 `INVALID_HANDLE` |
| `set-param` | `{setting:"radius_logarithmic",value}` | `dgcSetBrushSetting(ctx, currentBrush, enum(setting), value)` → 无有效 brush 时 `INVALID_HANDLE` |
| `stroke` | `{points:[{x,y,p,tiltX,tiltY},…]}` | 首点 `dgcBeginStroke`，后续 `dgcStrokeTo(…,0)`，末 `dgcEndStroke` |
| `clear` | `{op:"clear"}` | `dgcClear(ctx, …)`（默认底色或上次 canvas background） |
| `undo` | `{op:"undo"}` | `dgcUndo(ctx)` → 当前 `NOT_IMPLEMENTED` |
| `export` | `{op:"export",path}` | `dgcExportPNG(ctx, path)`（`--out` 覆盖） |

- setting 名 → 枚举映射：`radius`→`DGC_SETTING_RADIUS(0)`、`hardness`→`DGC_SETTING_HARDNESS(1)`、`opacity`→`DGC_SETTING_OPACITY(2)`、`radius_logarithmic`→`DGC_SETTING_RADIUS_LOG(3)`（§4.0.6 示例用 `radius_logarithmic`）。
- `stroke` 点流：每点读 `x/y/p/tiltX/tiltY`（缺省 `p=1,tiltX=0,tiltY=0`）；`isPredicted=0`。
- 错误策略：任一 op 返回非 `DGC_OK` → stderr 打印 op 名 + `dgcGetLastError()`；默认**继续**执行后续 op（best-effort，保证「全操作闭环」不因 brush 未实现而中断），`--strict`（可选）可切换为「首错即止非零退出」。最终 `dgcExportPNG` 失败则非零退出。

### 4. 离屏渲染调用链（`script_runner.cpp`）

```
dgcCreate()                                    // CtxGuard 持有
dgcSetOffscreenSurface(ctx, w, h)              // → VkBackend::initOffscreen
dgcClear(ctx, bg.r, bg.g, bg.b, bg.a)          // → clearCanvas（同步）
[seed/fixed-time → dgcSetRandomSeed/dgcSetFixedTime]
[ops 按序解释执行]
dgcFlush(ctx)                                  // ★ 见步骤 5：drain 屏障
dgcExportPNG(ctx, outPath)                     // → readback + stb_image_write
// CtxGuard 析构 → dgcDestroy → engine stop/join
```

### 5. 补齐 flush/drain 屏障（`Engine::flush` + `dgcFlush`）★ 关键

现状：`dgcStrokeTo` 只入队，渲染线程异步 `composite`；CLI 直接 `dgcExportPNG` 会读到未合成的画布。加同步屏障：

- `Engine::flush()`：在**调用线程**上（非引擎三线程）——先等 `pending_input_` 空（mutex 保护），再轮询等 `input_to_brush_.empty()`、`brush_to_render_.empty()`（`RingBuffer::empty()` 已提供）；最后以渲染线程「已完成一轮 composite」的 epoch 计数（`std::atomic<std::size_t>`，renderLoop 每 composite 后 `fetch_add`）作屏障，等它追平已提交批次，保证 flush 返回时所有已提交输入已合成。纯等待 + 原子读，无新堆所有权。
- `dgcFlush(DgcContext*)`：NULL 校验 → `DGC_ERR_NULL_CONTEXT`；`engine->flush()` → `DGC_OK`；engine 未 running 直接返回 `DGC_OK`。
- 这是 §4.0.3「CLI 离屏同步单线程」语义的落地：三线程引擎仍存在，但 CLI 在 export 前用 flush 把时序压成确定性 drain（B5-3 的 golden 逐字节一致在此基础上才成立）。

### 6. 确定性 / 参数化接线（透传）

- `seed`/`fixed-time` 直接透传 `dgcSetRandomSeed`/`dgcSetFixedTime`（B1-6/B1-7 已实现 setter 语义，CLI 不新增逻辑）。无 seed/fixed-time 字段时**不调用**对应 setter（保留 `dgcCreate` 默认 seed=0 / override=false）。
- `set-param`/`set-color` 透传 `dgcSetBrushSetting`/`dgcSetBrushColor`；因当前无有效 brush handle，如实返回 `INVALID_HANDLE`（见 R2，不 fake 成功）。

## 风险与备选

1. **flush/drain 屏障设计（关键，触及 SDK）**：`dgcStrokeTo` 异步入队 vs `dgcExportPNG` 同步读回存在竞态，必须加 `Engine::flush()` + `dgcFlush()`。备选 A：复用 `dgcRender` 语义改为「离屏下 flush」——但 `dgcRender` 文档是「每帧调用」，UI 每帧调它若阻塞会拖慢 UI，故**不用**；备选 B：CLI 侧忙等 `dgcReadbackPixels` 直到稳定——无 drain 语义、脆弱，**不用**。首选新增 `dgcFlush`（additive，ABI 向后兼容）。若评审认为「加 23 号函数越权」，退回备选：B5-2 范围只交 CLI + 用「提交后短暂 sleep + 重读」的临时同步，并把正式 flush 标记为 B5-3 前置项（**需人工裁决，不自行选**）。
2. **无 L5 内核 → brush/undo/stroke 不可视（B3-1 未做）**：`dgcCreateBrush`/`dgcSetBrush`/`dgcLoadBrushFromMyb`/`dgcUndo` 返回 `NOT_IMPLEMENTED`，`dgcSetBrushSetting`/`dgcSetBrushColor` 因无有效 handle 返回 `INVALID_HANDLE`；`NullPaintKernel::strokeTo` 空 → **stroke 不产 dab，画布仅显示底色**。CLI 如实透传 + `dgcGetLastError` 报错 + best-effort 继续，保证「全操作闭环」在**命令映射层面**成立、不崩溃；**像素级笔刷痕迹与 golden 一致依赖 B3-1 + B5-3**。计划在 PR/README 明确标注该边界，避免把「全操作闭环」误读为「能画出来」。
3. **「与窗口渲染结果一致」无法验证**：B2-1 为离屏 only（`present()` no-op，无 swapchain），本仓库无窗口路径。§阶段7「与窗口结果一致」以**离屏 PNG 为唯一基准**，窗口一致性留待消费者 PC UI 联调时补验（不在本任务）。
4. **lavapipe 环境差异**：headless Vulkan 在无 GPU/驱动时不可用（§7 风险表）。降级：`dgcSetOffscreenSurface` 在 `supportsOffscreen()==false`（Null 后端）时返回 `NOT_IMPLEMENTED`，CLI 报错并**优雅失败**（非零退出 + 清晰错误），不崩溃；host CI 冒烟用 lavapipe（B2-1 已通）。
5. **JSON 库离线不可得**：`third_party/` 无 nlohmann。首选 curl 单头 `nlohmann/json.hpp`（MIT）；失败则**降级**写最小 JSON 子集解析器（仅覆盖 §4.0.6 schema：对象/数组/字符串/数字/布尔，嵌套一层 op 对象），并把「非完整 JSON 兼容」列为已知边界。不引入运行时 JSON 依赖（host 可 apt `nlohmann-json3-dev` 作开发期对照，但不进链接）。
6. **C ABI additive 变更**：新增 `dgcFlush` 使公开函数 22→23。需在 `dgc_paint_c_api.h` 头注明版本增量、保持 `extern "C"` + 纯 C 可解析（不破坏 B1-4「纯 C 编译器可解析」验收）；`test_c_api_header.c` 可补一条 `dgcFlush` 符号引用断言。
7. **CLI 是宿主不是库**：`cli/` 只链 `dgc_paint`、只 include 公开头，**不**把 CLI 的 JSON 解析/脚本逻辑并入 `dgc_paint`（SDK 保持无第三方 JSON 依赖）；`DGCPAIN_BUILD_CLI` 仅 host 开，Android preset 不构建（`NOT DGCPAIN_ANDROID` 守卫）。
