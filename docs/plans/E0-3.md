> 任务线：线0-环境 · 承接原 B1-2。状态/审核 SOT 见 `docs/tasks/任务线.md`，本计划不改。
> 依据：`docs/tasks/detail/环境搭建与项目骨架.md` E0-3；`DGCPaint_技术规划.md` §2.3/§2.4；`docs/调研/路线整理.md` §顶层 CMake 选项设计 / §7.7；`docs/env/env-setup.md`（E0-1 已交付，软/硬依赖口径）。

## 目标

一份 CMake 编出 SDK 库 `dgc_paint`，目录树立住：多 toolchain（host-linux / host-windows / android-arm64）+ 路线 option（`DGCPAIN_KERNEL_*` / `DGCPAIN_RENDER_*` + 合法性检查）+ 目录树骨架（`kernels/` `render/` 空占位，默认链 Null）。

## 验收标准（抄自 `docs/tasks/detail/环境搭建与项目骨架.md` · E0-3）

- `cmake --preset host-linux` 配置通过，编出 `libdgc_paint`（或静态库）。
- 不链接 GLFW/ImGui。
- `android-arm64` preset 文件存在；无 NDK 时失败信息可读。
- `host-windows` preset 文件存在；在 VS2026 上实测归后续 Windows 环境线（本任务只保证文件存在）。

（任务书「产出」还要求：路线 option 与规划 §2.3 合法性检查一致；目录树 `core/ sdk_api/ kernels/ render/ tests/ third_party/` 骨架，`kernels/ render/` 空占位、无实现时链 Null、不得填真实 dab/compute；PUBLIC include 仅 `sdk_api/`。）

## 设计

### 1. 顶层 `CMakeLists.txt`

```cmake
cmake_minimum_required(VERSION 3.22)
project(dgc_paint LANGUAGES C CXX)

# ── 双 toolchain 分发 ──
if(CMAKE_SYSTEM_NAME STREQUAL "Android")
    set(DGCPAIN_ANDROID ON)
else()
    set(DGCPAIN_ANDROID OFF)
endif()

# ── 路线选项（绘画内核 L5）──
option(DGCPAIN_KERNEL_BRUSH   "Route E: self-developed C++ kernel" ON)   # 主线
option(DGCPAIN_KERNEL_MYPAINT "Route A: link libmypaint"            OFF)
option(DGCPAIN_KERNEL_GPU     "Route B: GPU compute kernel"         OFF)

# ── 路线选项（渲染后端 L4）──
option(DGCPAIN_RENDER_VULKAN  "Routes A/E/B: Vulkan compute"        ON)
option(DGCPAIN_RENDER_SKIA    "Route C: Skia GLES3"                 OFF)
option(DGCPAIN_RENDER_BGFX    "Route D: bgfx"                       OFF)

# 通用选项
option(DGCPAIN_BUILD_TESTS    "Build host unit tests"               ON)

# ── 合法性检查（抄自 路线整理.md「顶层 CMake 选项设计」，与 §2.3 口径一致）──
if(DGCPAIN_KERNEL_GPU AND NOT DGCPAIN_RENDER_VULKAN)
    message(FATAL_ERROR "Route B (GPU kernel) requires Vulkan renderer")
endif()
if(DGCPAIN_KERNEL_MYPAINT AND DGCPAIN_KERNEL_BRUSH)
    message(FATAL_ERROR "Cannot enable both mypaint and brush kernel simultaneously")
endif()

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# ── SDK 库目标：E0-3 先立住库与内部 sources；真实内核/渲染后续任务加入 ──
add_library(dgc_paint
    core/null/null_paint_kernel.cpp
    core/null/null_render_backend.cpp
)
target_include_directories(dgc_paint
    PUBLIC  ${CMAKE_CURRENT_SOURCE_DIR}/sdk_api   # 唯一对外 include（B1-4 才放头）
    PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}           # 让 #include "core/..." 生效
)

# ── 路线分发：E0-3 各子目录尚不存在，`if(EXISTS ...)` 守卫生效为空操作；
#    Null 桩已在库目标内无条件编译，作为当前默认 L4/L5。B2-1/B3-1 落地后：
#    各自新增 kernels/brush/、render/vulkan/ 等 CMakeLists.txt，此处守卫自动接管 ──
if(DGCPAIN_KERNEL_BRUSH AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/kernels/brush/CMakeLists.txt)
    add_subdirectory(kernels/brush)
endif()
if(DGCPAIN_KERNEL_MYPAINT AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/kernels/mypaint/CMakeLists.txt)
    add_subdirectory(kernels/mypaint)
endif()
if(DGCPAIN_KERNEL_GPU AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/kernels/gpu/CMakeLists.txt)
    add_subdirectory(kernels/gpu)
endif()
if(DGCPAIN_RENDER_VULKAN AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/render/vulkan/CMakeLists.txt)
    add_subdirectory(render/vulkan)
endif()
if(DGCPAIN_RENDER_SKIA AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/render/skia/CMakeLists.txt)
    add_subdirectory(render/skia)
endif()
if(DGCPAIN_RENDER_BGFX AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/render/bgfx/CMakeLists.txt)
    add_subdirectory(render/bgfx)
endif()

# ── 测试（host only）──
if(DGCPAIN_BUILD_TESTS AND NOT DGCPAIN_ANDROID)
    enable_testing()
    add_subdirectory(tests)
endif()
```

要点：
- 6 个路线 option 命名与默认值**严格对齐** `DGCPaint_技术规划.md` §2.3 / `路线整理.md`「顶层 CMake 选项设计」/ `README.md`「路线切换」：`DGCPAIN_KERNEL_{BRUSH,MYPAINT,GPU}`、`DGCPAIN_RENDER_{VULKAN,SKIA,BGFX}`；默认 `BRUSH=ON`、`VULKAN=ON`，其余 OFF。
- **不加** `DGCPAIN_BUILD_JNI` / `DGCPAIN_BUILD_CLI` / `platform/` / `ui/`：v5.0 口径已决定 SDK 不含 JNI/UI 消费者（见 `共同基座.md`「明确不做」、`README.md`「不在本仓库」）。
- `add_library` 不带 STATIC/SHARED 关键字 → 默认静态（host 产出 `libdgc_paint.a`，满足「或静态库」）；后续 B5-1 编 android `.so` 时再切 SHARED。
- 合法性检查两处 `FATAL_ERROR` 与 `路线整理.md` 一致（Route B 需 Vulkan；mypaint 与 brush 互斥）。

### 2. `CMakePresets.json`

按 `DGCPaint_技术规划.md` §2.4 结构，**删除** `DGCPAIN_BUILD_JNI`/`DGCPAIN_BUILD_CLI`/`DGCPAIN_BUILD_SDK`（本 SDK 无 JNI/CLI/独立 sdk 开关），保留路线选项与 `DGCPAIN_BUILD_TESTS`：

- `host-linux`：generator Ninja，binaryDir `${sourceDir}/build/host-linux`，`CMAKE_BUILD_TYPE=Debug`，`DGCPAIN_KERNEL_BRUSH=ON`、`DGCPAIN_RENDER_VULKAN=ON`、`DGCPAIN_BUILD_TESTS=ON`。
- `host-windows`：同上，binaryDir `${sourceDir}/build/host-windows`。
- `android-arm64`：generator Ninja，binaryDir `${sourceDir}/build/android-arm64`，`toolchainFile="$env{ANDROID_NDK_HOME}/build/cmake/android.toolchain.cmake"`，`ANDROID_ABI=arm64-v8a`、`ANDROID_PLATFORM=android-30`、`ANDROID_STL=c++_static`，`DGCPAIN_KERNEL_BRUSH=ON`、`DGCPAIN_RENDER_VULKAN=ON`、`DGCPAIN_BUILD_TESTS=OFF`（不设 `CMAKE_BUILD_TYPE`）。
- `buildPresets` 三项分别指到对应 configurePreset。

「无 NDK 时失败信息可读」：`ANDROID_NDK_HOME` 未设时 `$env{...}` 展开为空，toolchainFile 变成不存在的 `/build/cmake/android.toolchain.cmake`，CMake 报「Could not find toolchain file」，与 `docs/env/env-setup.md` §6 排查口径一致。

### 3. 目录骨架与 `tests/CMakeLists.txt`

- `sdk_api/` `kernels/` `render/` `third_party/` 用 `.gitkeep` 占位（git 不跟踪空目录）。
- `tests/CMakeLists.txt`：
  ```cmake
  add_executable(compile_null compile_null.cpp)
  target_link_libraries(compile_null PRIVATE dgc_paint)
  add_test(NAME compile_null COMMAND compile_null)
  ```
  复用既有 `compile_null.cpp`，链接 `dgc_paint` 即证明库目标可编译可链接；**不**在此写 C API 用例（那是 B5-1 的 headless C API 闭环）。

## 步骤

1. 建目录 `sdk_api/` `kernels/` `render/` `third_party/`，各放 `.gitkeep`。
2. 写顶层 `CMakeLists.txt`（按「设计 1」）。
3. 写 `CMakePresets.json`（按「设计 2」）。
4. 写 `tests/CMakeLists.txt`（按「设计 3」）。
5. 自检（对照验收四条）：
   - `cmake --preset host-linux` → `cmake --build --preset host-linux`，确认 `build/host-linux/libdgc_paint.a` 产出（或静态库）。
   - `ctest --test-dir build/host-linux --output-on-failure` 通过（compile_null 冒烟）。
   - `grep -RniE "glfw|imgui" CMakeLists.txt CMakePresets.json tests/` 无命中；确认未 `find_package(GLFW)`。
   - `git status` 只含本计划列出的新增文件，无 `ui/ platform/ app/`；`CMakePresets.json` 含 `host-windows` 与 `android-arm64` 两个 preset 名。
   - 可选：未设 `ANDROID_NDK_HOME` 时 `cmake --preset android-arm64` 报「Could not find toolchain file」即可读失败（不阻断 host 验收）。

## 风险

- **合法性检查口径**：§2.3 正文未显式写 `FATAL_ERROR`，实际检查在 `路线整理.md`「顶层 CMake 选项设计」。以 `路线整理.md` 两处为准（Route B 需 Vulkan；mypaint+brush 互斥），避免评审时口径不一致。
- **默认 BRUSH/VULKAN 为 ON 但无真实实现**：分发统一用 `if(EXISTS .../CMakeLists.txt)` 守卫，Null 桩无条件编译进库 → 默认配置仍可 configure/build，不会因缺子目录报错。
- **preset `version` 与 cmake 下限**：`version: 6` 需 cmake ≥ 3.25，而 `cmake_minimum_required` 是 3.22。env-setup 建议 host 装 3.31+，实际无碍；若执行机 cmake 恰为 3.22–3.24，降 preset `version` 到 3 即可。
- **include 路径**：Null 源文件用 `#include "core/..."`，需 `PRIVATE` 指向仓库根；`PUBLIC` 只留 `sdk_api/`（当前空，指向空目录无副作用），不得把 `core/` 暴露为 PUBLIC（对外 ABI 边界）。
- **越界**：不得填真实 dab/compute、不得提前写 `dgc_paint_c_api.h`（B1-4）、不得引入 GLFW/ImGui、不得建 `ui/ platform/ app/`。`tests/` 只接线既有 `compile_null.cpp`，不写 C API 用例（B5-1）。
