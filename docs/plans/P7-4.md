## 0. 先行代码核验（本计划撰写时实读结果）

1. `sdk_api/dgc_paint_c_api.h:82`：`dgcStrokeTo(DgcContext*, float x, float y, float pressure, float tiltX, float tiltY, int isPredicted)` —— **签名无时间参数**，真机 MotionEvent 时间戳无处可传。新声明应插在 `dgcStrokeTo`（:82）之后、`dgcEndStroke`（:83）之前。
2. `sdk_api/dgc_paint_c_api.cpp:216-225`：`dgcBeginStroke` 在「predictor 激活且非 override」时注入 `default_step_us = 1e6/min_output_rate_hz`（默认 180Hz→5555µs）；`:237` `dgcStrokeTo` 的 `t_us = time_stepper.next()`（每点固定步长）——**合成时间基准**（分析文档 §3 原因 A）。
3. `core/types.h:7`：`StrokePoint { float x,y,pressure,tilt_x,tilt_y; std::uint64_t t_us; bool is_predicted; }` —— `t_us` 为 `uint64_t`。
4. `core/stroke_predictor.cpp:46-50`（WobbleSmoother）、`:225-232`（KalmanPredictor）用 `dt=(t_us-last_t_us)/1e6`；`:399-422` `Predict` 沿 `kalman_.velocity()` 外推 `prediction_interval_ms`（默认 16ms）。**t_us 消费是通用的**——喂真实单调 t_us 即按真实节奏校准，模型器无需改。
5. `core/stroke_predictor.cpp:163-168`（PositionModeler）与 `:227`（KalmanPredictor）对 `dt<=0` 有防御分支（`integrate_dt=kStepS` / 跳过 predict）——真实时间戳同刻/乱序不崩溃、不产生 NaN。
6. `sdk_api/dgc_paint_c_api.cpp:450-478`：`dgcSetBrushSetting` 首次写 modeler 项才 `std::make_unique<StrokeModeler>()` 惰性创建注入（默认 **passthrough**，未动滑杆则无预测）；`predictor_handle_` 为**非拥有裸指针**（所有权在 engine 的 unique_ptr，`c_api.cpp:56-59` 注释）。`model_params` 默认 `min_output_rate_hz=180.0`、`prediction_interval_ms=16.0`（`stroke_predictor.h:48,91`）。
7. `core/determinism.h:11,55-80`：`DeterminismState.override_time` + `FixedTimeStepper`——override 时 `next()=n*step`，非 override 有 default_step 时 `next()=n*default_step`，否则恒 0。`dgcSetFixedTime`（`c_api.cpp:437-443`）置 `override_time=true`。**确定性约束：override 下 t_us 必须走合成步长，真实时间戳只在非 override（交互）路径生效**。
8. `jni/paint_android_jni.cpp:51-52`：`nativeStrokeTo(x,y,pressure)` → `dgcStrokeTo(g_sdk, x, y, pressure, 0.f, 0.f, 0)`；`PaintNative.kt:19` `external fun nativeStrokeTo(x,y,pressure)`；`PaintScreen.kt:230-239` `onDrag` 调 `ctx.nativeStrokeTo(cx, cy, 0.5f)` —— 消费者当前不传任何时间。

## 1. 目标

新增 C API 真实时间戳入口 `dgcStrokeToAt(ctx, x, y, pressure, tiltX, tiltY, isPredicted, t_us)`；`paint-android` JNI/Compose 把 `PointerInputChange.uptimeMillis*1000`（µs）透传。使 modeler 卡尔曼速度按真实输入节奏校准、预测点沿真实笔速外推，预测墨迹稳定领先 ~`prediction_interval_ms`，不再「抢跑+回扯」。override 模式（`dgcSetFixedTime` 确定性路径）行为完全不变。

**不承诺**：预测完全消除所有延迟（转向/收笔处外推天然有误差，见 §7）；预测墨迹「及时上屏可见」依赖 P7-3。

## 4. 详细设计

### 4.1 C API：`dgcStrokeToAt`（真实时间戳）

`dgc_paint_c_api.h`（`dgcStrokeTo` 声明后新增）：

```c
/* 真实时间戳输入（P7-4）：t_us 为真实事件时间（微秒，笔画内需单调不减；绝对或
 * 笔画内相对均可）。提供后 modeler 的卡尔曼速度/预测长度按真实输入节奏校准，
 * 不再用合成固定步长（dgcBeginStroke 的 default_step 只作非 At 路径回退）。
 * 与 dgcSetFixedTime（override）互斥：override 时 t_us 被忽略、仍走固定时间步，
 * 保证 CLI/批处理/确定性测试的 golden 可复现。同刻/乱序 t_us（dt<=0）由
 * PositionModeler/KalmanPredictor 既有防御分支处理，不崩溃。
 * 建议：真机交互（非 override）路径用 MotionEvent 时间戳；无真实时间的调用方
 * 继续用 dgcStrokeTo（合成步长回退）。 */
DGC_API int dgcStrokeToAt(DgcContext* ctx, float x, float y, float pressure,
                          float tiltX, float tiltY, int isPredicted, double t_us);
```

`dgc_paint_c_api.cpp`：

```cpp
int dgcStrokeToAt(DgcContext* ctx, float x, float y, float pressure,
                  float tiltX, float tiltY, int isPredicted, double t_us) {
    if (ctx == nullptr) { g_last_error = DGC_ERR_NULL_CONTEXT; return DGC_ERR_NULL_CONTEXT; }
    // 确定性优先：override 时忽略真实 t_us，走固定时间步（golden 可复现）。
    std::uint64_t ts;
    if (ctx->impl_->determinism.override_time) {
        ts = ctx->impl_->time_stepper.next();
    } else {
        ts = std::uint64_t(t_us);
    }
    StrokePoint p{x, y, pressure, tiltX, tiltY, ts, (isPredicted != 0)};
    StrokeEvent ev{StrokeEventType::StrokePoint, p};
    if (!ctx->impl_->engine->submitInput(ev)) {
        g_last_error = DGC_ERR_QUEUE_FULL;
        return DGC_ERR_QUEUE_FULL;
    }
    g_last_error = DGC_OK;
    return DGC_OK;
}
```

> 引擎 `inputLoop`（`core/engine.cpp`）对 `StrokeEvent.point.t_us` 原样透传进 `StrokeModeler::Update`——真实时间戳自此进入模型器，引擎无需改。

### 4.2 消费端透传 MotionEvent 时间

`jni/paint_android_jni.cpp`：

```cpp
extern "C" JNIEXPORT void JNICALL
Java_com_dgcamp_paint_jni_PaintNative_nativeStrokeToAt(JNIEnv*, jobject,
        jfloat x, jfloat y, jfloat pressure, jdouble tUs) {
    if (g_sdk) dgcStrokeToAt(g_sdk, x, y, pressure, 0.f, 0.f, 0, tUs);
}
```

`PaintNative.kt`：`external fun nativeStrokeToAt(x: Float, y: Float, pressure: Float, tUs: Double)`

`PaintScreen.kt` `onDrag`：`ctx.nativeStrokeTo(cx, cy, 0.5f)` → `ctx.nativeStrokeToAt(cx, cy, 0.5f, change.uptimeMillis * 1000.0)`；保留 `scheduler.onInput()`。`dgcBeginStroke`（`onDragStart`）不变——Begin 点经 `Reset()` 不喂模型器，无需时间。

> `PointerInputChange.uptimeMillis` 为 Long(ms)，`*1000` 得 µs；同一手势内单调递增。`nativeStrokeToAt` 用 `jdouble` 承载 µs，避免 Long→Int 截断。

### 4.3 SDK host 回归测试 `tests/test_stroke_predictor_real_time.cpp`

沿用 `test_stroke_predictor.cpp` 结构与本地的 `StrokeModeler` 直接构造（不新增共享头）。设计：

1. 构造 `StrokeModeler`，`Configure(StrokeModelParams{})`（默认 180Hz / 16ms 预测）。
2. **60Hz 真实时间戳**：以 `t_us = k * 16667`（真实 60Hz 间隔）喂一条沿 +X 匀速直线（每点位移 dx 恒定），`Update` + `Predict` 收集输出。
   - 断言 A（速度校准）：真实点（`is_predicted==false`）相邻间距推断速度 ≈ 位移/16667µs（容差 ±30%），而非 180Hz 合成基准下的 3x 高估。
   - 断言 B（预测不抢跑）：`Predict` 产出预测点沿 +X 延伸总长 ≈ `velocity * 16ms`（容差 ±40%），无 3x 级过度外推；末点 `is_predicted==true`。
3. **同刻/乱序边界**：连喂两个 `t_us` 相同或倒退的点，断言不崩溃、输出无 NaN（`std::isfinite` 检查）。
4. **override 等价（C API 层）**：`dgcSetFixedTime` + `dgcStrokeToAt`（任意 t_us）→ 与 `dgcStrokeTo` 输出一致（同 seed/固定时间下点列或渲染像素一致），证明真实时间戳未渗入 override 路径。

`tests/CMakeLists.txt`：在 `test_stroke_predictor`（:186-189）同块追加四联注册。

> 说明：验收 1 的 host 测试以「60Hz 真实间隔喂点流」复现真机真实输入节奏，是**同等调用模式**的自动化替代（喂给 modeler 的 t_us 序列与真机 `uptimeMillis` 一致）；真机「领先 ~预测间隔」的手感项（验收 3）无法纯 host 替代，需真机人工验证（§4.6）。

### 4.4 SDK 工程约束（dgc_paint 库）

- **所有权 / RAII**：`dgcStrokeToAt` 无新堆所有权——`StrokePoint p` / `StrokeEvent ev` 均为栈值，`t_us` 为值传递；不引入任何裸 `new`/`delete`。既有 `predictor_handle_` 是**非拥有裸指针**（所有权在 engine 的 `unique_ptr`，非本任务引入，不动）。
- **Pimpl 边界**：新增导出符号 `dgcStrokeToAt` 仅出现在 `dgc_paint_c_api.h`（`DGC_API` 宏），`DgcContext` 仍为不透明句柄，C ABI 不暴露 `Impl`/`StrokeModeler`/`FixedTimeStepper` 等内部类型；实现经 `ctx->impl_` 访问，与既有 `dgcStrokeTo` 同构。
- **确定性 override 保留**：override 分支优先，真实 `t_us` 仅交互路径生效；`test_modeler_deterministic`/`test_determinism`（同 seed 两次渲染像素一致）必须保持绿。
- **泄漏验证**：`cmake -DDGCPAIN_SANITIZE=ON` host 重建，跑新增 + 既有 modeler/determinism 测试，ASan/LSan 零泄漏零 UB。
- **IDE/clangd 误报口径**：host 无 `compile_commands.json` 时 clangd 的 `pp_file_not_found`/`unknown_typename` 是误报，以实际 g++/cmake 构建 + ctest 结果为准，不写入计划/验收。

## 6. 风险与冲突核查

### 6.1 冲突核查（对既有性能/架构决策，逐条确认不削弱）

| 既有决策 | 是否受影响 | 结论 |
|---|---|---|
| **determinism override 合成步长**（`dgcSetFixedTime` → `override_time` → `n*step`） | 否 | `dgcStrokeToAt` 的 override 分支仍走 `time_stepper.next()`，真实 t_us 仅非 override 路径生效；**显式保留**，`test_modeler_deterministic`/`test_determinism` 必须保持绿（验收 2） |
| **批量 composite / 攒批上限兜底**（`kMaxBatchStamps`/`kMaxBatchDurationMs`） | 否 | `dgcStrokeToAt` 只改「点流的 t_us 取值」，不触碰 `submitInput`/`renderLoop`/flush 合批逻辑；事件量级与 `dgcStrokeTo` 相同 |
| **readback 节流去抖**（P7-2 `kMinFlushIntervalMs`） | 否 | 不触及 readback/flush 路径 |
| **modeler 卡尔曼速度/预测长度**（`dt` 驱动 `velocity`/`prediction_interval_ms`） | 否 | 真实 t_us 正是让 `dt` 正确，属修复而非绕开；`prediction_interval_ms` 默认值不变 |
| **引擎三线程编排 / inputLoop 透传** | 否 | `inputLoop` 对 `point.t_us` 原样透传，无引擎改动 |
| **惰性激活 predictor（passthrough 默认）** | 否 | 不强制启用 modeler；只有动过滑杆才激活，非 override 且未激活时 `dgcStrokeToAt` 直填真实 t_us 也不会影响 passthrough（无 modeler 消费 t_us） |

### 6.2 风险

1. **依赖 P7-3 上屏解耦**（分析文档 §3 原因 B）：预测墨迹要「及时上屏」才能让用户看到领先效果；若 P7-3 未完成，预测点即便生成也会被 vsync 读回节拍吞掉。**验收 3 以 P7-3 落地为前提**；SDK 侧（验收 1/2/4/5）不依赖 P7-3，可并行开发。
2. **resampler 上采样放大事件量**：真实 60Hz 输入下 `min_output_rate=180Hz` 对每对真实点间补 2 个中间点，加预测点后每输入点展开约 6 事件（多于合成基准的 4）。SDK 计算仍足够快，但 Mali 下 composite 批变大——若真机帧时恶化，调低 `min_output_rate_hz`（D6-1 滑杆暴露）。
3. **同刻事件**：Android 高频下偶发 `eventTime` 相同，`dt=0` 走防御分支不崩溃；过密同刻会削弱速度估计（不影响正确性）。
4. **真机人工验收**：验收 3 需真机，host 自动化（验收 1/2/4/5）为可验证替代，真机数据人工补齐，如实标注，不豁免。

## 7. 不做

- **不改 `core/stroke_predictor` 模型器算法**（WobbleSmoother/Resampler/PositionModeler/Kalman/StrokeEnd 均不动）——真实时间戳已足够让它们按真实节奏工作；调参交给 D6-1 滑杆与消费端。
- **不改 `dgcStrokeTo` 既有签名/ABI**（新增 `dgcStrokeToAt` 而非改签名）。
- **不做预测自校准/自适应**（按实时延迟动态调预测间隔）——超出本期，留作后续。
- **不做 SurfaceView/GL 上屏**（属 P7 线后续，与 P7-3 一致）。
