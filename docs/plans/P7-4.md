# P7-4 实施计划 · modeler 预测生效（真实时间戳）

> 任务书：`docs/调研/AD平台手感延迟分析.md` §3（合成时间基准是预测失效的结构性根因）；任务线行：`docs/tasks/任务线.md` P7-4。
> 依赖：P7-1、P7-2（P7-2 执行中）；预测墨迹及时上屏依赖 P7-3（读回/上屏 vsync 解耦），作为**共需前置**（见 §6 风险 1）。
> 范围：**SDK C API 增加真实时间戳入口 + `paint-android` 透传 MotionEvent 时间**；`core/stroke_predictor` 模型器逻辑不改（其 `t_us` 消费已通用），仅补回归测试。

## 0. 先行代码核验（计划撰写前实读结果）

1. `sdk_api/dgc_paint_c_api.h:82`：`dgcStrokeTo(DgcContext*, float x, float y, float pressure, float tiltX, float tiltY, int isPredicted)` ——**签名无时间参数**，真机 MotionEvent 时间戳无处可传。
2. `sdk_api/dgc_paint_c_api.cpp:216-225,237`：`dgcBeginStroke` 在「predictor 激活且未 override」时注入 `default_step_us = 1e6/min_output_rate_hz`（180Hz→5555µs）；`dgcStrokeTo` 的 `t_us = time_stepper.next()`（每点固定步长）——**合成时间基准**（分析文档 §3 原因 A）。
3. `core/stroke_predictor.cpp:211-263`：`KalmanPredictor::Update` 用 `dt = (t_us - last_t_us)/1e6`；`:391-423` `Predict` 沿 `kalman_.velocity()` 外推 `prediction_interval_ms`。**t_us 消费是通用的**——只要喂进真实单调递增的 t_us，速度估计与预测长度即按真实节奏校准，无需改模型器。
4. `core/stroke_predictor.cpp:163-168,227`：`PositionModeler`/`KalmanPredictor` 对 `dt<=0`（同刻/乱序时间戳）已有防御分支（`integrate_dt=kStepS` / 跳过 predict）——真实时间戳出现 `eventTime` 相同或非单调时不崩溃。
5. `core/engine.cpp:158-189` `inputLoop`：predictor 激活时对 `StrokePoint` 调 `Update`/`Predict` 并把 `out` 展开成事件（`t_us` 原样透传），Begin/End 触发 `Reset()`（Begin 点不喂模型器）。**引擎无需改**。
6. `jni/paint_android_jni.cpp:50-53`：`nativeStrokeTo(x,y,pressure)` → `dgcStrokeTo(g_sdk, x, y, pressure, 0.f, 0.f, 0)` ——消费者当前不传任何时间。
7. 确定性约束（`core/determinism.h` + `dgcSetFixedTime`）：override 模式下 t_us 必须走合成步长，**真实时间戳只在非 override（交互）路径生效**，保 CLI/测试 golden 确定性不破坏。

## 1. 目标

新增 C API 真实时间戳入口 `dgcStrokeToAt(ctx, x, y, pressure, tiltX, tiltY, isPredicted, t_us)`；`paint-android` JNI/Compose 把 `MotionEvent.uptimeMillis*1000` 透传。使 modeler 的卡尔曼速度按真实输入节奏校准、预测点沿真实笔速外推，预测墨迹可稳定领先 ~prediction_interval，不再「抢跑+回扯」。override 模式（确定性）行为完全不变。

**不承诺**：预测完全消除所有延迟（外推在转向/收笔处天然有误差，见 §7）；预测墨迹及时上屏依赖 P7-3。

## 4. 详细设计

### 4.1 C API：`dgcStrokeToAt`（真实时间戳）

`dgc_paint_c_api.h`（紧邻 `dgcStrokeTo` 声明后新增）：

```c
/* 真实时间戳输入（P7-4）：t_us 为真实事件时间（微秒，笔画内需单调不减；绝对或
 * 笔画内相对均可）。提供后 modeler 的卡尔曼速度/预测长度按真实输入节奏校准，
 * 不再用合成固定步长（dgcBeginStroke 的 default_step 只作非 At 路径回退）。
 * 与 dgcSetFixedTime（override）互斥：override 时 t_us 被忽略、仍走固定时间步，
 * 保证 CLI/批处理/确定性测试的 golden 可复现。同刻/乱序 t_us（dt<=0）由
 * PositionModeler/KalmanPredictor 既有防御分支处理，不崩溃。
 * 建议：真机交互（非 override）路径用 MotionEvent 时间戳；无真实时间的调用方
 * 继续用 dgcStrokeTo（合成步长回退）。 */
DGC_API int dgcStrokeToAt(DgcContext* ctx, float x, float y, float pressure,
                          float tiltX, float tiltY, int isPredicted, double t_us);
```

`dgc_paint_c_api.cpp`：

```cpp
int dgcStrokeToAt(DgcContext* ctx, float x, float y, float pressure,
                  float tiltX, float tiltY, int isPredicted, double t_us) {
    if (ctx == nullptr) { g_last_error = DGC_ERR_NULL_CONTEXT; return DGC_ERR_NULL_CONTEXT; }
    // 确定性优先：override 时忽略真实 t_us，走固定时间步（golden 可复现）。
    std::uint64_t ts;
    if (ctx->impl_->determinism.override_time) {
        ts = ctx->impl_->time_stepper.next();
    } else {
        ts = std::uint64_t(t_us);
    }
    StrokePoint p{x, y, pressure, tiltX, tiltY, ts, (isPredicted != 0)};
    StrokeEvent ev{StrokeEventType::StrokePoint, p};
    if (!ctx->impl_->engine->submitInput(ev)) {
        g_last_error = DGC_ERR_QUEUE_FULL;
        return DGC_ERR_QUEUE_FULL;
    }
    g_last_error = DGC_OK;
    return DGC_OK;
}
```

> 引擎 `inputLoop`（`core/engine.cpp:158-189`）对 `StrokeEvent.point.t_us` 原样透传进 `StrokeModeler::Update`——真实时间戳自此进入模型器，无需引擎改动。

### 4.2 消费端透传 MotionEvent 时间

`jni/paint_android_jni.cpp`：

```cpp
extern "C" JNIEXPORT void JNICALL
Java_com_dgcamp_paint_jni_PaintNative_nativeStrokeToAt(JNIEnv*, jobject,
        jfloat x, jfloat y, jfloat pressure, jdouble tUs) {
    if (g_sdk) dgcStrokeToAt(g_sdk, x, y, pressure, 0.f, 0.f, 0, tUs);
}
```

`PaintNative.kt`：

```kotlin
external fun nativeStrokeToAt(x: Float, y: Float, pressure: Float, tUs: Double)
```

`PaintScreen.kt` `onDrag`：

```kotlin
onDrag = { change, _ ->
    change.consume()
    strokeActive = true
    // P7-4：真实时间戳（Compose PointerInputChange.uptimeMillis 与 MotionEvent.eventTime
    // 同源），模型器速度/预测按真实节奏校准。
    ctx.nativeStrokeToAt(cx, cy, 0.5f, change.uptimeMillis * 1000.0)
    // ...原 dirty/scheduler.onInput() 语义保留（P7-3 接入后为 scheduler.onInput()）
}
```

> `PointerInputChange.uptimeMillis` 为 Long(ms)，`*1000` 得 µs；同一手势内单调递增。`dgcBeginStroke` 不变（Begin 点经 `Reset()` 不喂模型器，无需时间）。

### 4.3 SDK host 回归测试 `tests/test_stroke_predictor_real_time.cpp`

沿用 `test_stroke_predictor.cpp` 的结构与本地断言辅助（不新增共享头）。设计：

1. 构造 `StrokeModeler`，`Configure(StrokeModelParams{})`（默认 180Hz / 16ms 预测）。
2. **60Hz 真实时间戳**：以 `t_us = k * 16667`（真实 60Hz 间隔）喂一条沿 +X 匀速直线（每点位移 dx 恒定），`Update` + `Predict` 收集输出。
   - 断言 A（速度校准）：输出中真实点（`is_predicted==false`）相邻间距对应的**推断速度** ≈ 位移/16667µs（容差 ±30%），而非 180Hz 合成基准下的 3x 高估。
   - 断言 B（预测不抢跑）：`Predict` 产出的预测点沿 +X 延伸总长 ≈ `velocity * 16ms`（容差 ±40%），无 3x 级过度外推；末点 `is_predicted==true`。
3. **同刻/乱序边界**：连喂两个 `t_us` 相同或倒退的点，断言不崩溃、输出无 NaN（`std::isfinite` 检查）。
4. **override 路径**：等价用 C API 层 `dgcSetFixedTime` + `dgcStrokeToAt`（任意 t_us）→ 与 `dgcStrokeTo` 输出一致（断言同 seed/固定时间下渲染像素一致或点列一致）。

CMakeLists 注册：`tests/CMakeLists.txt` 内 `test_stroke_predictor`/`test_modeler_*` 同块追加四联（`add_executable`/`target_include_directories`/`target_link_libraries`/`add_test`）。

### 4.4 工程约束

- **所有权**：`dgcStrokeToAt` 无新堆所有权；`StrokePoint p`/`StrokeEvent ev` 栈值。无裸 new/delete。
- **ABI**：新增导出符号（`dgcStrokeToAt`），既有 `dgcStrokeTo` 签名不变；`DgcContext` 仍不透明。`dgc_paint_c_api.h` 的 `DGC_API` 导出宏沿用。
- **确定性**：override 分支优先，真实 t_us 仅在交互路径生效；`test_modeler_deterministic` 必须保持绿。
- **泄漏验证**：`-DDGCPAIN_SANITIZE=ON` host 重建跑新增 + 既有 modeler 测试，ASan/LSan 零泄漏零 UB。

## 6. 风险

1. **依赖 P7-3 上屏解耦**：预测墨迹要「及时上屏」才能让用户看到领先效果；若 P7-3 未完成，预测点即便生成也会被 vsync 读回节拍吞掉（分析文档 §3 原因 B）。**P7-4 的验收 3 以 P7-3 落地为前提**；SDK 侧（验收 1/2/4/5）不依赖 P7-3，可并行开发。
2. **resampler 上采样放大事件量**：真实 60Hz 输入下 `min_output_rate=180Hz` 会对每对真实点间补 2 个中间点（`stroke_predictor.cpp:115-128`），加上 3 个预测点，每输入点展开 ~6 事件（比合成基准下的 4 更多）。SDK 计算仍足够快（三线程），但真机弱 GPU（Mali）下 composite 批变大——若真机帧时恶化，调低 `min_output_rate_hz` 或对齐真实输入率（D6-1 滑杆已暴露）。
3. **同刻事件**：Android 高频下偶发 `eventTime` 相同（合并），`dt=0` 走防御分支不崩溃；但过密同刻会削弱速度估计——可接受（不影响正确性）。
4. **真机人工验收**：验收 3 需真机；host 自动化（验收 1/2/4/5）为可验证替代，真机数据人工补齐，如实标注。

## 7. 不做

- **不改 `core/stroke_predictor` 的模型器算法**（WobbleSmoother/Resampler/PositionModeler/Kalman/StrokeEnd 均不动）——真实时间戳已足够让它们按真实节奏工作；调参（预测间隔/平滑）交给 D6-1 滑杆与消费端。
- **不改 `dgcStrokeTo` 既有签名/ABI**（新增 `dgcStrokeToAt` 而非改签名）。
- **不做预测自校准/自适应**（如按实时延迟动态调预测间隔）——超出本期，留作后续。
- **不做 SurfaceView/GL 上屏**（属 P7 线后续，与 P7-3 §7 一致）。
