## 1. 目标

消费端（paint-pc）可切换笔刷颜色、可开关垂直同步；SDK 侧补「vsync 归属」文档说明。

## 2. 现状（关键发现，规划前已核查）

### 2.1 颜色：C API 入口已落地，但「颜色 → 渲染」链路是断的（必须补桥接）

- `sdk_api/dgc_paint_c_api.h:115`：`dgcSetBrushColor(ctx, brush, r, g, b, a)` 存在（B1-6 落地）。
- `sdk_api/dgc_paint_c_api.cpp:355-367`：`dgcSetBrushColor` 仅把 RGBA 写入 `ctx->impl_->brush_colors[brush]`（`std::unordered_map<DgcBrush, std::array<float,4>>`，声明于 `.cpp:43`）。
- **该 map 全库无任何读取点**（`grep brush_colors` 仅命中声明 + 写入两处）→ 颜色是死存储，改了不落地到渲染。
- `sdk_api/dgc_paint_c_api.cpp:180-189`：`dgcCreateBrush` 返回 `DGC_INVALID_BRUSH` + `DGC_ERR_NOT_IMPLEMENTED`（B1-4 遗留，多笔刷管理未接线）。→ 消费端拿不到合法笔刷句柄。
- `core/engine.cpp:153`：引擎在 `brushLoop` 开头 `kernel_->createBrush(BrushParams{})` 建**唯一默认笔刷**，后续所有笔画都用它。`kernels/brush/brush_kernel.cpp:25` `next_handle = 1` → 该默认笔刷句柄**确定性地 = 1**。
- 内核已有颜色通道但未接线：`kernels/brush/brush.h:38` `Brush::setColor(h,s,v)`（HSV）**无任何调用者**；`kernels/brush/brush.cpp:164-165` dab 生成时 `hsv_to_rgb_float(ColorH,ColorS,ColorV)` → `StampData.r/g/b`。即只要把 HSV 写进该 Brush，下一笔 dab 即变色（`StampData` 无 alpha 字段，见风险 R4）。

**结论**：任务行「已支持」指 C API 入口存在；要满足验收「改颜色后新笔画为该颜色」，必须补「C API 颜色 → 内核默认笔刷」的桥接。

### 2.2 vsync：SDK 纯离屏，无 swapchain/present，无 vsync 概念

- `render/vulkan/vk_backend.h:10-11`：`无窗口 headless 离屏模式…不创建 swapchain，present() no-op`（已注明）。
- `render/vulkan/vk_backend.cpp:906`：`present()` no-op。
- 消费端 paint-pc 现为 GLFW + OpenGL 上屏：`src/app.cpp:118` `glfwSwapInterval(1)` 开 vsync；`src/app.cpp:195` `glfwSwapBuffers` 上屏。**「关闭垂直同步」= 切换 `glfwSwapInterval(0/1)`，纯消费端行为，SDK 离屏渲染路径不动。**

## 3. 验收标准（抄自任务书 §D6-3）

- 改颜色后，新笔画为该颜色；旧笔迹不变。
- 关闭垂直同步后帧率不再被刷新率锁定（高刷屏实测帧率 > 刷新率或帧间隔波动，**人工记录**）；重新开启恢复同步。
- SDK 文档注明 vsync 归属；离屏渲染路径零回归（host ctest 全绿）。

评审「通过」必要条件（任务书末表）：取色改笔画颜色生效；vsync 开关实测帧率变化有人工记录；SDK 离屏路径零回归。

## 5. 步骤

### 步骤 1 — SDK 颜色桥接（内核 + C API）

1. `kernels/brush/color.h`：加 `rgb_to_hsv_float`（HSV 反变换；边界：r=g=b=0 → s=0、h=0；s=0 时 h 保持 0 避免 `fmod` 噪声）。
2. `core/interfaces/i_paint_kernel.h`：加纯虚 `setBrushColor`。
3. `core/null/null_paint_kernel.h/.cpp`：空实现（no-op）。
4. `kernels/brush/brush_kernel.h/.cpp`：实现 `setBrushColor`——`lock_guard` 查 `impl_->brushes.find(handle)`，找到则解锁后 `brush->setColor(h,s,v)`（与既有 `beginStroke`/`strokeTo` 同款「锁只守注册表、不解锁后调用」模式）。未找到 handle：no-op 返回（不崩）。
5. `core/engine.cpp`：默认笔刷创建上移到 `start()`，`brushLoop` 复用成员 `default_brush_`（消除「C API 设置颜色时笔刷尚未创建」的竞态，见 R3）。
6. `sdk_api/dgc_paint_c_api.h`：加 `DGC_DEFAULT_BRUSH` 宏 + 注释。
7. `sdk_api/dgc_paint_c_api.cpp`：`dgcSetBrushColor` 校验不变（`brush == DGC_INVALID_BRUSH` → `DGC_ERR_INVALID_HANDLE`），写 `brush_colors[brush]` 后追加 `ctx->impl_->kernel->setBrushColor(brush, r, g, b, a)`。

### 步骤 2 — SDK vsync 文档

1. `README.md` 加「垂直同步（vsync）归属」小节：SDK 纯离屏（`render/vulkan/vk_backend.h` 无 swapchain、`present()` no-op），**无 vsync 概念**；「关闭垂直同步」属于消费端 present 模式（GLFW `glfwSwapInterval(0)` / Vulkan presentMode `FIFO→IMMEDIATE`），SDK 不提供也不触碰；离屏渲染路径零改动。
2. `sdk_api/dgc_paint_c_api.h` 在 `dgcRender` 声明处补注释：离屏渲染无 present/vsync，上屏与帧节奏由消费端负责。

### 步骤 3 — 消费端颜色取色器接线（paint-pc）

1. `src/app.cpp` `Impl` 增加 `float brushColor[4] = {0.f, 0.f, 0.f, 1.f}`（默认黑，与内核默认 ColorH/S/V=0 一致）。
2. run() 内新增 ImGui 调试窗口「Brush / Display」：`ImGui::ColorEdit4("Brush Color", impl->brushColor)`，变更即调 `dgcSetBrushColor(impl->sdk, DGC_DEFAULT_BRUSH, brushColor[0], brushColor[1], brushColor[2], brushColor[3])`；返回值非 0 时 `stderr` 打印 `dgcGetLastError()`。
3. 验证语义：改色后下一笔用新色、旧笔迹不变（读回贴图叠加，非全清重绘）。

### 步骤 4 — 消费端 vsync 开关接线（paint-pc）

1. `Impl` 增加 `bool vsyncOn = true`（与 `app.cpp:118` `glfwSwapInterval(1)` 初始态一致）。
2. ImGui 内加 `ImGui::Checkbox("VSync", &impl->vsyncOn)`，回调/每帧检测变化即 `glfwSwapInterval(impl->vsyncOn ? 1 : 0)`（即时生效）。

### 步骤 5 — 测试与验证

- **host ctest 零回归 + 新覆盖**：`cmake --preset host-linux && cmake --build --preset host-linux && ctest --test-dir build/host-linux --output-on-failure`。新增内核级断言（步骤 1）后全绿（含 B5-3 确定性、B4-1 CPU/GPU 对照、B2-1 离屏读回）。
- **泄漏验证**：`cmake --preset host-linux-sanitize && cmake --build --preset host-linux-sanitize && ctest --test-dir build/host-linux-sanitize --output-on-failure`（`DGCPAIN_SANITIZE=ON` 的 ASan/LSan，确认颜色桥接引入的改动零泄漏、零裸 new/delete）。
- **Android 编译**：`export ANDROID_NDK_HOME=… && cmake --preset android-arm64 && cmake --build --preset android-arm64`（SDK 有改动时仍编出 `.a`/`.so`）。
- **paint-pc 人工验收**（照任务书）：
  1. 取色器改颜色 → 新笔画为新色，旧笔迹不变；
  2. 关 vsync → 高刷屏实测帧率 > 刷新率或帧间隔波动（人工记录），重开恢复同步；
  3. SDK 文档可查到 vsync 归属说明。

## 6. SDK 工程约束（必含，落于设计/风险）

- **所有权 RAII**：颜色桥接全程不引入裸 `new`/`delete`。`BrushKernel::Impl::brushes` 继续 `unordered_map<BrushHandle, unique_ptr<Brush>>`；`Brush` 内 RNG 继续 `unique_ptr<IRandomSource>`。新增成员一律值语义或 `unique_ptr`（`Engine::default_brush_` 为值类型 `BrushHandle`，无堆所有权）。
- **Pimpl / 不透明句柄**：对外 C ABI 不暴露内部类型。`DgcContext` 仍是 `struct DgcContext { struct Impl; unique_ptr<Impl> impl_; }`；`DGC_DEFAULT_BRUSH` 只是 `uint64_t` 字面量宏，不暴露 `Brush`/`BrushKernel`；新增虚函数只出现在内部 `IPaintKernel`，不进 `dgc_paint_c_api.h`。
- **泄漏验证方式**：`DGCPAIN_SANITIZE`（`host-linux-sanitize` preset，ASan/LSan）跑 `ctest` 全绿；`tests/test_ownership_loop.c` 已有 create/destroy 循环，颜色桥接若新增句柄持有也纳入该循环覆盖。

## 7. 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 颜色链路现状为死存储（`brush_colors` 无人读），任务行「已支持」仅指入口存在；若不补桥接，验收「改颜色后新笔画变色」必挂 | 步骤 1 显式补 `kernel->setBrushColor` 桥接，并用内核级单测锁定 |
| R2 | `dgcCreateBrush` 为 NOT_IMPLEMENTED，消费端拿不到合法句柄 | 用 `DGC_DEFAULT_BRUSH = 1`（引擎唯一默认笔刷、`next_handle=1` 确定性）；不改 C ABI 签名 |
| R3 | 引擎默认笔刷在 `brushLoop` 异步创建，C API 可能在笔刷创建前设色（单测同步调用即触发）→ `setBrushColor` 找不到句柄 no-op | 默认笔刷创建上移到 `Engine::start()`，句柄存成员，`start()` 返回前即存在；`setBrushColor` 对缺失句柄 no-op 不崩 |
| R4 | `StampData` 无 alpha，内核 dab 色为 straight RGB；`dgcSetBrushColor` 的 `a` 无法直接进 dab（不透明度走 `dgcSetBrushSetting(DGC_SETTING_OPACITY)`） | 文档/注释注明：alpha 为 ABI 兼容保留，本期内核用 RGB（D6-1 若接 OPACITY 再串）；验收「新笔画为该颜色」按 RGB 判定 |
| R5 | RGB→HSV 反变换边界（纯黑 s=0 时 h 未定义） | `color.h` 显式处理 s=0 → h=0，避免 NaN 进 dab |
| R6 | 消费端 submodule 钉 `heads/main`，SDK 新提交需同步到 paint-pc 才能生效 | 两仓边界清晰：SDK 改动在本 worktree 合并后，paint-pc 更新 `sdk/` submodule 指针再接线验收 |
