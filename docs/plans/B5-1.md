## 目标

线5-闭环的两根支柱落地：

1. **headless ctest 调 C API**：新增一个**纯 C**（只 `#include "dgc_paint_c_api.h"`，不 include 任何内部头）的 ctest，在**无窗口/无显示**的 host 环境下走完一整条 C API 会话——`dgcCreate → dgcSetOffscreenSurface → dgcClear → dgcBeginStroke/dgcStrokeTo×N/dgcEndStroke → dgcFlush → dgcReadbackPixels（断言笔迹处像素相对底色变化）→ dgcExportPNG → dgcDestroy`。即 §阶段1 验收里的 `test_c_api` 闭环：证明 C API 不需要 UI 宿主就能 headless 跑通并产出可读回像素。
2. **android-arm64 编出 .so**：`cmake --preset android-arm64`（`ANDROID_NDK_HOME` 满足 E0-3 口径，即 NDK r27+/r28 就位时）能 configure + build 出 `build/android-arm64/libdgc_paint.so`（arm64-v8a）。核心是补上 E0-3 预留的「Android 切 SHARED」与「Android 无 libshaderc → 预编译 SPIR-V」两条路径。

## 验收标准（人工授权派生，非任务书原文）

1. **headless C API 闭环 ctest**：`tests/test_c_api_headless.c` 为纯 C（不 include `render/`、`core/` 等内部头），在 host headless 下跑完整 C API 会话：建上下文 → 离屏表面 → 清屏 → 笔画输入 → `dgcFlush` → `dgcReadbackPixels` 断言「笔迹覆盖处相对底色变暗、笔迹外仍为底色」→ `dgcExportPNG` 落盘 → 销毁。运行不依赖显示服务器、不依赖 GLFW（lavapipe 软件光栅 headless），`ctest` 全绿。
2. **运行时能力探测**：`test_c_api_headless.c` 用 `dgcSetOffscreenSurface` 返回值分支（同 `test_c_api_b1_6.c` 先例）——Vulkan 后端激活时走真实 readback/export 断言；`DGCPAIN_RENDER_VULKAN=OFF`（Null 后端）时三函数回 `DGC_ERR_NOT_IMPLEMENTED`、跳过像素断言但仍通过。两种 host 配置都能 ctest 通过。
3. **android-arm64 .so 产物**：NDK 就位时 `cmake --preset android-arm64 && cmake --build --preset android-arm64` 成功，产出 `build/android-arm64/libdgc_paint.so`（`file` 显示 `ELF ... ARM aarch64`）。无 NDK 时沿用 E0-3 口径：报「Could not find toolchain file」等**可读失败**，属软依赖、**不阻断 host 编译与 ctest**。
4. **Android 切 SHARED、host 不回归**：`CMAKE_SYSTEM_NAME STREQUAL "Android"` 时 `add_library(dgc_paint SHARED ...)` 产 `.so`；host 保持默认静态 `libdgc_paint.a`，既有全部 host ctest 不改行为、全绿。
5. **Android shader 编译路径（去 libshaderc）**：NDK 无 `libshaderc`，Android 下 `render/vulkan/CMakeLists.txt` 不再 `find_library(shaderc)`，改走「NDK 自带 `glslc` 构建期把 `brush_composite.comp` 预编译成 SPIR-V 并内嵌为字节数组头」；`VkBackend::CompileBrushShader` 在 `DGCPAIN_PRECOMPILED_SPV` 下直接返回内嵌 SPIR-V（跳过运行时 shaderc）。host 保持 B2-1 的运行时 shaderc 路径**完全不变**。
6. **SDK 工程约束**：本任务新增/改动代码零裸 `new/delete` 所有权（`make_unique`/`unique_ptr`）；对外 ABI 面仍只经 `DgcContext` 不透明句柄 Pimpl 隐藏内部类型（`dgc_paint_c_api.h` 不新增任何 C++ 内部类型；`.so` 的公开面只有 C API 符号）；host `DGCPAIN_SANITIZE=ON` 构建 ASan/LSan 对新增测试零泄漏。
7. **不越界**：不新增 `ui/` `platform/` `app/`，不加 GLFW/ImGui/JNI/Gradle；`.so` 由 SDK CMake 直接产出（非 Android Studio/Gradle），不写任何消费者代码。

非目标（不在 B5-1）：Android 窗口/swapchain/present 路径与 JNI（阶段 4/平台线）；`.so` 符号可见性收紧（`-fvisibility=hidden`，见风险 R6，仅记不强制）；Android 上真实跑 Vulkan compute（本任务只保证**编出** .so，不含 arm64 设备/模拟器运行验证）；golden PNG 逐字节一致（B5-3）。

### 2. `render/vulkan/CMakeLists.txt`：分 host / Android 两路

在 `find_library(SHADERC_LIBRARY ...)` 之后、`if(NOT SHADERC_INCLUDE_DIR ...)` 之前插入 Android 分支：

```cmake
if(DGCPAIN_ANDROID)
    # Android NDK 无 libshaderc，改走 glslc 构建期预编译 SPIR-V + 内嵌。
    find_program(GLSLC_BIN NAMES glslc)
    if(NOT GLSLC_BIN)
        message(FATAL_ERROR "glslc not found (NDK provides it under toolchains/llvm/prebuilt/*/bin)")
    endif()
    execute_process(COMMAND ${GLSLC_BIN} -fshader-stage=compute
        ${CMAKE_CURRENT_SOURCE_DIR}/brush_composite.comp
        -o ${CMAKE_CURRENT_BINARY_DIR}/brush_composite.spv
        RESULT_VARIABLE _rc)
    if(NOT _rc EQUAL 0)
        message(FATAL_ERROR "glslc failed compiling brush_composite.comp")
    endif()
    file(READ ${CMAKE_CURRENT_BINARY_DIR}/brush_composite.spv _spv HEX)
    string(REGEX REPLACE "([0-9a-f][0-9a-f])" "0x\\1," _spv_array "${_spv}")
    string(APPEND _spv_array "0x0")
    configure_file(${CMAKE_CURRENT_SOURCE_DIR}/brush_composite_spv.h.in
                   ${CMAKE_CURRENT_BINARY_DIR}/brush_composite_spv.h @ONLY)
    target_compile_definitions(dgc_paint PRIVATE DGCPAIN_PRECOMPILED_SPV=1)
    # 不 find_library(shaderc)、不 target_link_libraries shaderc
else()
    # host：保留既有 find_library(shaderc) + 运行时编译（B2-1 不变）
endif()
```

要点：
- host 侧（含既有 `SHADERC_INCLUDE_DIR`/`SHADERC_LIBRARY` 校验与 `target_link_libraries(... shaderc)`）整体包进 `else()` 分支，**不改 host 行为**。
- `brush_composite_spv.h.in` 模板：
  ```cpp
  #pragma once
  // 由 CMake 在 Android 构建期用 glslc 从 brush_composite.comp 生成（单一权威源仍是 .comp）。
  static const unsigned char kBrushCompositeSpv[] = { @SPV_C_ARRAY@ };
  ```
  （`configure_file` 里用 `@SPV_C_ARRAY@` 替换为 `@_spv_array@`；注意 `configure_file` 的 `@ONLY` 语义，模板占位符名需与 `set()` 变量名对应，执行时按实际变量名对齐。）
- Vulkan 头/loader：NDK sysroot 自带 `vulkan/vulkan.h` 与 `libvulkan.so`，`find_path(VULKAN_INCLUDE_DIR)` / `find_library(VULKAN_LIBRARY NAMES vulkan)` 在 NDK toolchain 的 `CMAKE_FIND_ROOT_PATH` 下可直接命中，**不需改动**这两行。

### 3. `vk_backend.cpp`：`CompileBrushShader` 加预编译 SPIR-V 分支

```cpp
#ifdef DGCPAIN_PRECOMPILED_SPV
#include "brush_composite_spv.h"
#endif

std::vector<uint32_t> CompileBrushShader(std::string* err) {
#ifdef DGCPAIN_PRECOMPILED_SPV
    const size_t nbytes = sizeof(kBrushCompositeSpv);
    // SPIR-V 指令长度对齐到 4 字节（glslc 产出的 spv 天然 4 对齐）。
    std::vector<uint32_t> spv(nbytes / sizeof(uint32_t));
    std::memcpy(spv.data(), kBrushCompositeSpv, nbytes);
    return spv;
#else
    shaderc::Compiler compiler;
    // ... 既有 shaderc 运行时编译，原样保留 ...
#endif
}
```

要点：
- `brush_composite_spv.h` 只在 `DGCPAIN_PRECOMPILED_SPV` 下 include（避免 host 构建缺文件）。
- host 侧 `CompileBrushShader` 行为零变化（既有 `test_offscreen`/`test_brush_offscreen` 回归不受影响）。

### 4. `tests/test_c_api_headless.c`（纯 C，headless C API 闭环）

结构与 `test_brush_offscreen.cpp` 的「C API 端到端」段一致，但**纯 C、不 include 内部头**：

```c
#include "dgc_paint_c_api.h"
#include <stdio.h>
#include <string.h>
/* CHECK 宏 + failures 计数，同 test_c_api_b1_6.c */
int main(void) {
    DgcContext* ctx = dgcCreate();
    /* 离屏：能力探测分支 */
    int rc = dgcSetOffscreenSurface(ctx, 64, 64);
    if (rc == DGC_OK) {
        dgcClear(ctx, 1.0f, 1.0f, 1.0f, 1.0f);  /* 白底 */
        dgcBeginStroke(ctx, 8.0f, 32.0f, 0.5f, 0.0f, 0.0f);
        for (int x = 12; x <= 56; x += 4)
            dgcStrokeTo(ctx, (float)x, 32.0f, 0.5f, 0.0f, 0.0f, 0);
        dgcEndStroke(ctx);
        dgcFlush(ctx);
        unsigned char buf[64 * 64 * 4];
        memset(buf, 0, sizeof(buf));
        CHECK(dgcReadbackPixels(ctx, buf) == DGC_OK, "readback OK");
        /* 笔迹中心 (32,32) 变暗、角落 (0,0) 仍白底 */
        CHECK(buf[(32*64+32)*4+0] < 200, "stroke darkened center");
        CHECK(buf[(0*64+0)*4+0] > 200 && buf[0*64*4+1] > 200 && buf[0*64*4+2] > 200,
              "corner stays white");
        CHECK(dgcExportPNG(ctx, "/tmp/b5_1_headless.png") == DGC_OK, "exportPNG OK");
    } else {
        CHECK(rc == DGC_ERR_NOT_IMPLEMENTED, "offscreen -> NOT_IMPLEMENTED (null backend)");
        /* Null 后端：跳过像素断言 */
    }
    dgcDestroy(ctx);
    return failures == 0 ? 0 : 1;
}
```

## SDK 工程约束落点（RAII / Pimpl / 零泄漏）

- **所有权设计（谁拥有）**：本任务不改 `dgc_paint` 库内的对象所有权——`DgcContext`/`VkBackend`/`Brush`/`BrushKernel` 已由 B1-8/B2-1/B3-1 落成 RAII（`unique_ptr<Impl>`、`make_unique`）。新增的 `CompileBrushShader` 预编译分支只构造 `std::vector<uint32_t>`（值语义，RAII 自动释放），`test_c_api_headless.c` 只经 C API `dgcCreate/dgcDestroy` 成对管理，**零裸 new/delete 所有权**。
- **Pimpl 边界**：对外 ABI 面仍是 `sdk_api/dgc_paint_c_api.h` 的 `DgcContext` 不透明句柄 + 23 个 C 函数；`brush_composite_spv.h` 只是 `render/vulkan/` 内部生成头（`PRIVATE` include，`DGCPAIN_PRECOMPILED_SPV` 下才消费），不进入 PUBLIC include，不暴露任何内部 C++ 类型；`.so` 对外公开面只有 C API 符号（内部 C++ 符号可见性收紧见风险 R6，非本任务强制项）。
- **泄漏验证方式**：`DGCPAIN_SANITIZE=ON`（host GCC/Clang，ASan + LSan）跑新增 `test_c_api_headless` 的 create/stroke/readback/destroy 全流程 + 既有 `test_ownership_loop`，断言零泄漏；Android 下 `DGCPAIN_SANITIZE` 顶层已显式排除（NDK Clang 无 LSan），不误加。

| R4 | **Android 上 Vulkan 头/loader 探测**：`find_path(vulkan/vulkan.h)` / `find_library(vulkan)` 是否命中 NDK sysroot | .so 配置失败 | NDK toolchain 已把 sysroot 注入 `CMAKE_FIND_ROOT_PATH`，默认命中；若未命中则 `find_path`/`find_library` 加 `HINTS ${ANDROID_NDK_HOME}/toolchains/llvm/prebuilt/*/sysroot` |
| R5 | **预编译 SPIR-V 与 runtime shaderc 结果不一致**（版本/优化差异） | host/Android 视觉差异 | 单一权威源仍是 `brush_composite.comp`；host 仍走 runtime shaderc，Android 走 glslc（同为 Khronos 官方工具链，SPIR-V 语义一致）；本任务只要求「编出 .so」，不要求 arm64 像素一致性 |
| R6 | **`.so` 默认导出全部符号**（内部 C++ 符号泄漏），ABI 面不干净 | 符号冲突/ODR 隐患 | 记入非目标；若后续 JNI 消费需要，可加 `-fvisibility=hidden` + C API 显式 `__attribute__((visibility("default")))` 导出宏，B5-1 不强做 |
| R7 | **`configure_file` 内嵌二进制转义**（`0x..,` 数组在 `@ONLY` 下的正确性） | 生成头损坏 | 备选：`xxd -i` 生成 `.h`，或改 `execute_process` + 自写小脚本生成数组；执行时先 `cmake --build` 后 `nm`/`strings` 抽查 `kBrushCompositeSpv` 长度 = `.spv` 文件字节数 |
| R8 | **`test_c_api_headless.c` 的 readback 像素断言过强/过弱**（不同驱动 ±1 LSB，§4.0.3） | 断言抖动 | 只断言「笔迹中心 < 200、角落 > 200」这类宽阈值（相对底色明显变化），不做逐字节；沿用 `test_brush_offscreen` 已验证的阈值口径 |
| R9 | **host 静态库 vs Android 共享库的 `target_link_libraries` 差异** | 链接失败 | 顶层 `add_library` 分支后，`render/vulkan`、`kernels/brush` 等子目录的 `target_sources(dgc_paint ...)` 与 `target_link_libraries(dgc_paint ...)` 对同一目标继续生效，不受 SHARED/STATIC 切换影响；执行时按 host 先回归、Android 后验证顺序 |
