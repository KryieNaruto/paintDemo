## 3. 关键决策：缩放实现位置（消费端视口变换优先）

- **优先方案（本计划采用）**：缩放显示与坐标映射全部在消费端 `paint-pc` 完成，SDK 不动。
  - 依据：SDK 纯离屏、无 swapchain、`present()` no-op（`render/vulkan/vk_backend.h`），视口/显示变换属 UI 层职责（`docs/调研/路线整理.md` §7.5「UI 层只做窗口表面/输入归一化/每帧渲染」）。离屏画布保持原生分辨率（= 帧缓冲尺寸），缩放只作用在「读回纹理 → 屏幕 quad」的**采样子矩形** 与「光标 → 画布坐标」的**逆映射**上，SDK 渲染/合成路径完全不变。
  - 结果：SDK 零代码改动，不新增画布变换 C API。
- **兜底**：若执行中暴露「必须 SDK 支持」（预期不需要，如画布变换 API），则回退本计划重评，新增 C API 必须保持 C ABI 不暴露内部类型、Pimpl 隐藏实现（见 §8）。

## 5. 坐标映射正确性（缩放核心）

现有两套坐标空间已存在：光标内容坐标（`glfwGetCursorPos`，逻辑单位）→ 画布像素（离屏表面 = 帧缓冲尺寸），由 `MapCursorToCanvas` 按 `canvas/content` 比例换算（处理 DPI 缩放）。叠加缩放后的完整链：

1. **光标内容坐标 → 帧缓冲/画布像素**（已有 DPI 换算，保留）：
   `fx = cx * canvasW / contentW`，`fy = cy * canvasH / contentH`
2. **视口变换（新增）**：画布子矩形 `[viewX, viewY, viewW, viewH]`（画布像素）显示为整个窗口。取 `viewW = canvasW / zoom`、`viewH = canvasH / zoom`（zoom ≥ 1 放大，0 < zoom < 1 缩小，均需 clamp 上下限）。中心锚定（zoom 绕窗口中心，最简单且满足落点一致性）：
   `viewX = canvasW/2 - canvasW/(2*zoom)`，`viewY = canvasH/2 - canvasH/(2*zoom)`
3. **光标 → 画布像素（逆映射，落点正确性的关键）**：
   `px = viewX + fx / zoom`，`py = viewY + fy / zoom`
4. **显示端采样 UV**：全屏 quad 的 UV 从 `[0,1]` 改为画布子矩形归一化坐标，UV(0,0) = `(viewX/canvasW, viewY/canvasH)`，UV(1,1) = `((viewX+viewW)/canvasW, (viewY+viewH)/canvasH)`；沿用现有 shader 的 `vUV.y` 翻转（`1.0 - vUV.y`）。

要点：
- **落点正确性与锚点无关**：逆映射（第 3 步）是验收「画笔落点与光标一致」的唯一依赖；zoom 锚定是显示层选择，二者解耦。
- **pan（平移）**：任务书按钮清单只列「+ / − / 滚轮 / 重置」，不要求平移。`viewX/viewY` 结构天然支持 pan（后续可加拖动平移），本期 pan 恒为 0，不纳入验收。
- **除零保护**：`MapCursorToCanvas` 已有「任一尺寸 ≤ 0 输出 (0,0)」；扩展时保留，并 clamp `zoom` 到合理区间（如 `[0.1, 8.0]`），避免 `zoom=0` 除零。

## 6. 清空（`dgcClear` + `dgcFlush` + 重新读回显示）

接线细节与**执行顺序**（关键正确性点）：

1. **先 `dgcFlush(ctx)`** —— 排空 3 线程引擎里已提交但尚未合成的笔画（`dgcFlush` 阻塞至所有已提交笔画合成完毕，见 `sdk_api/dgc_paint_c_api.cpp:382`）。
2. **再 `dgcClear(ctx, 0.96f, 0.95f, 0.91f, 1.0f)`** —— 同步清屏（`VkBackend::clearCanvas` → `ClearCanvasLocked` 内 `vkCmdClearColorImage` + `SubmitAndWait`，见 `render/vulkan/vk_backend.cpp:777-795`），立即生效。
3. **下一帧 `dgcReadbackPixels(ctx, rgba)` 读回显示** —— 主循环已每帧读回，清空后自动在下一帧显示干净画布。

> 说明：任务书原文表述为「`dgcClear` + `dgcFlush` + 重新读回显示」。正确实现顺序应为 **flush 在前、clear 在后**——若按字面「先 clear 后 flush」，队列中未合成的笔画会在 clear 之后被 composite 回画布，破坏「无残留」验收。`dgcClear` 本身已同步（`SubmitAndWait`），clear 之后无需再 flush 等待 clear 生效。

- **清空色与 init 一致**：清空按钮传 `(0.96, 0.95, 0.91, 1.0)`（纸白底色），与 `app.cpp` init 的 `dgcClear` 及 `m->clearColor` 一致，避免屏幕底色与画布纹理出现色差缝。
- **清空后继续绘制**：`dgcClear` 不销毁设备/画布资源、不断流，engine 继续运行，后续 `dgcBeginStroke/StrokeTo/EndStroke` 正常，满足「清空后仍可继续绘制」。
- **按钮触发时机**：仅当无进行中笔画时触发（`strokeActive == false`），或触发前强制 `dgcEndStroke`，避免清空瞬间有半笔画入队。

## 8. SDK 工程约束（本任务 preferred 不触 SDK；记录以备若转 SDK 改动）

本任务 preferred 设计**零 SDK 代码改动**，故以下约束不触发；但若执行中转为「新增画布变换 C API」等 SDK 改动，必须回到以下约束并补验证：

- **所有权设计**：谁拥有、谁释放；一律 RAII，`std::unique_ptr` / `std::make_unique`，禁止裸 `new/delete` 持有所有权（现 `DgcContext` 唯一数据成员即 `std::unique_ptr<Impl>`，`sdk_api/dgc_paint_c_api.cpp:21-48` 为既有范式）。
- **Pimpl 边界**：对外 ABI 面经 `DgcContext` 不透明句柄隐藏实现，`dgc_paint_c_api.h` 只依赖 `<stdint.h>`、不含任何 C++ 符号；新增 C API 只加到 `DgcContext::Impl`，头不暴露内部类型。
- **泄漏验证方式**：`DGCPAIN_SANITIZE=ON`（`CMakeLists.txt:31-39`）host 构建启用 ASan+LSan，跑 `ctest` 全绿零泄漏（Android 下不适用）。

因 D6-2 不动 `dgc_paint` 库，上述三项落在「风险/兜底」而非必执行项；「SDK 有改动时 ctest 零回归」的验收天然满足（无改动即零回归）。

## 9. 风险

1. **清空顺序陷阱**：按任务书字面「clear→flush」会导致未合成笔画回写、残留（§6 已明确 flush→clear→readback 顺序）。
2. **DPI × zoom 双重缩放逆映射写错**：落点偏移。用 `coord_test` 纯函数回归 + 复用 `--coord-repro` 思路（十字 vs 笔迹落点 PNG 对照）验证逆映射。
3. **滚轮与 ImGui 抢事件**：鼠标悬停在 ImGui 面板上时滚轮会被面板吞掉。仅在光标位于画布区（非 `ImGui::IsWindowHovered` 面板）时响应滚轮缩放。
4. **采样滤镜语义**：当前 `GlCanvas` 用 `GL_NEAREST`，放大后呈马赛克（像素级）；「放大后显示清晰」指采样子矩形正确、无错位/模糊偏移，`GL_NEAREST` 满足。是否切 `GL_LINEAR` 为可选（平滑但引入插值，与「像素放大」的直观验证相斥），默认保持 `GL_NEAREST`。
5. **边界与 resize**：zoom clamp 下限防除零；窗口 resize 时 `canvasW/canvasH` 与视口需同步重算（保持中心锚定 / 比例），复用 `OnFramebufferSize` 现有同步逻辑。
6. **submodule 边界**：paint-pc 的 `sdk/` submodule 当前指向 main 最新 `c9515bd`（策略「不钉 pin、跟随 main」），本任务不改 submodule 指向。
