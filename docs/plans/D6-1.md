# D6-1 · 画笔参数设置（stroke modeler 参数 + 中文注释）

> 任务线：线6-调试 · 状态：可申领 · 依赖：B3-1、B1-6 · 审核：待审核
> 任务书：`docs/tasks/detail/调试按钮.md` §D6-1（验收标准逐字抄自该节，不自行增删）

## 1. 目标

让消费端（paint-pc）调试面板能实时调整 stroke modeler 的 9 个参数并看到笔迹变化；SDK 侧参数带中文注释；补齐 `DgcBrushSetting` 的 modeler 参数 settingId 并透传到 stroke predictor。

## 2. 验收标准（抄自任务书 §D6-1）

- `stroke_predictor.h` 9 参数均有中文注释。
- 调试面板可调整任意 modeler 参数，且**改参后笔迹明显变化**（如 spring_mass 越小越跟手、prediction_interval 越大预测点越远、wobble_timeout 影响抖动消除），每类参数至少一例人工记录。
- 非法 settingId 返回错误码，不崩溃。
- 未使用调试面板时（默认参数）与现有渲染**零回归**：host `ctest` 全绿（含 B5-3 确定性、B4-1 CPU/GPU 对照）；`android-arm64` preset 仍可编出 `.so`。

评审「通过」必要条件（任务书末表 D6-1 行）：stroke_predictor.h 9 参数中文注释；`DgcBrushSetting` 补齐 modeler 参数映射且非法 id 返回错误码；paint-pc 调试面板改参后笔迹变化有人工记录；host ctest 全绿。

## 3. 现状与关键发现

### 3.1 SDK 侧现状

- `core/stroke_predictor.h` 的 `StrokeModelParams` 9 个字段**无逐字段中文注释**（仅结构体顶部英文管线说明 + 分组注释）。字段：`wobble_timeout_ms`、`wobble_speed_floor`、`min_output_rate_hz`、`end_of_stroke_stopping_distance_mm`、`spring_mass_constant`、`spring_drag_constant`、`kalman_process_noise`、`kalman_measurement_noise`、`prediction_interval_ms`。
- `sdk_api/dgc_paint_c_api.h:93-100` `DgcBrushSetting` 仅 4 项：`RADIUS/HARDNESS/OPACITY/RADIUS_LOG`，`DGC_SETTING_COUNT=4`。
- `sdk_api/dgc_paint_c_api.cpp:337-353` `dgcSetBrushSetting` 只把值写进 `Impl::brush_settings[brush][settingId]`（`std::array<double, DGC_SETTING_COUNT>`），**不透传**到任何内核/预测器；settingId 越界返回 `DGC_ERR_INVALID_ARG`（满足「非法 id 返回错误码」基础语义）。

### 3.2 三个阻塞性缺口（本任务必须补，否则「调试面板改参」无从谈起）

1. **stroke predictor 未接入引擎**：`Engine::predictor_` 默认 `nullptr`（passthrough），`dgcCreate` 从不 `engine->setPredictor(...)`（B1-5 只做了槽位预留）。因此即便改 modeler 参数，笔迹也不会变 —— 与「改参后笔迹明显变化」验收直接冲突。
2. **无有效笔刷句柄**：`dgcCreateBrush` 恒返回 `DGC_INVALID_BRUSH` + `DGC_ERR_NOT_IMPLEMENTED`（B1-4 遗留，B3-1 R4 明确列入非目标）。而 `dgcSetBrushSetting(ctx, brush, ...)` 要求 `brush != DGC_INVALID_BRUSH`（否则 `DGC_ERR_INVALID_HANDLE`），调试面板拿不到句柄就无法调用。
3. **`DGC_SETTING_COUNT` 是 `brush_settings` 数组维度**：扩枚举后该数组维度随之扩到 13，需确认 `Impl::brush_settings` 同步（`std::array<double, DGC_SETTING_COUNT>` 会自动跟随枚举，无需改类型）。

## 4. 设计决策

### 4.1 `DgcBrushSetting` 扩项（C ABI 保持兼容）

**已有 4 项编号不变**（0-3，不重排），追加 9 个 modeler 项：

```c
typedef enum {
    DGC_SETTING_RADIUS     = 0, /* 半径 */
    DGC_SETTING_HARDNESS   = 1, /* 硬度 */
    DGC_SETTING_OPACITY    = 2, /* 不透明度 */
    DGC_SETTING_RADIUS_LOG = 3, /* §4.0.6 radius_logarithmic 别名 */
    /* ── 以下为 stroke modeler 参数（D6-1 补齐，语义归 core/stroke_predictor.h）── */
    DGC_SETTING_WOBBLE_TIMEOUT_MS = 4,
    DGC_SETTING_WOBBLE_SPEED_FLOOR = 5,
    DGC_SETTING_MIN_OUTPUT_RATE_HZ = 6,
    DGC_SETTING_END_OF_STROKE_STOPPING_DISTANCE_MM = 7,
    DGC_SETTING_SPRING_MASS_CONSTANT = 8,
    DGC_SETTING_SPRING_DRAG_CONSTANT = 9,
    DGC_SETTING_KALMAN_PROCESS_NOISE = 10,
    DGC_SETTING_KALMAN_MEASUREMENT_NOISE = 11,
    DGC_SETTING_PREDICTION_INTERVAL_MS = 12,
    DGC_SETTING_COUNT = 13
} DgcBrushSetting;
```

### 4.2 零回归约束下的「惰性激活」策略（核心决策）

验收要求「未使用调试面板时（默认参数）零回归」，而 `tests/fixtures/golden_determinism.png` 是**逐字节 diff**（`test_determinism.cpp:153-161`）。若 `dgcCreate` 默认把真实 `StrokeModeler` 注入引擎，默认笔迹就会平滑/预测，golden PNG 必然改变 → 违反零回归。

因此采用**惰性激活**：
- `dgcCreate` **不**创建/注入 predictor（保持 passthrough，默认零回归）。
- 首次对某个 modeler settingId 调用 `dgcSetBrushSetting` 时，才 `std::make_unique<StrokeModeler>()`、`Configure(model_params)`、`engine->setPredictor(std::move(p))`；之后每次 modeler 设置调用只 `Configure` 更新参数。

效果：默认参数（面板未动过）→ 渲染路径与现在完全一致（golden/确定性/CPU-GPU 对照全绿）；一旦动过 modeler 参数 → predictor 激活 → 笔迹明显变化（验收项）。

### 4.3 线程安全

`dgcSetBrushSetting` 由 UI 线程调用，predictor 的 `Update/Predict/Reset` 由引擎输入线程执行（`core/engine.cpp:128-142`）。惰性注入与后续 `Configure` 存在两个数据竞争点：

1. **`Engine::predictor_`（unique_ptr）的写入 vs 读**：`setPredictor` 移动赋值 vs `inputLoop` 读 `if (predictor_)`。
   - 处置：`Engine` 增 `std::mutex predictor_mutex_`；`setPredictor` 加锁移动；`inputLoop` 每事件取 `StrokeModeler* pred`（加锁拷贝裸指针后解锁，predictor 注入后**不再替换/销毁**，故裸指针在引擎生命周期内有效）。predictor 由 `Engine::predictor_`（unique_ptr）RAII 持有，与既有所有权一致。
2. **`Configure()`（内部 `Reset()`）vs `Update/Predict/Reset`**：`Configure` 会清空内部缓冲/弹簧/卡尔曼状态。
   - 处置：`StrokeModeler::Impl` 增一个 `std::mutex`，`Configure/Update/Predict/Reset` 四方法内部加锁（自包含，不改引擎/context 的线程契约；单线程路径与 B1-5 确定性测试无影响——互斥锁不影响算法确定性）。
   - 约定沿用 `BrushKernel::SetSeed` 的既有约定（风险 R5）：生产路径在「引擎空闲 / 笔画之间」改参；paint-pc 面板在 `strokeActive == false` 时提交设置（见 §7）。

### 4.4 有效笔刷句柄使能项（补 B1-4 遗留的最小实现）

为让调试面板/测试拿到非 0 句柄，`dgcCreateBrush` 做 B1-4 备选方案的最小落地：
- `DgcContext::Impl` 增 `uint64_t next_brush_handle_ = 1;`。
- `dgcCreateBrush` 返回 `next_brush_handle_++` 并置 `DGC_OK`（**不触 engine**，引擎仍用固定默认笔刷，符合 B3-1 R4）。
- `dgcSetBrush/dgcDestroyBrush/dgcLoadBrushFromMyb` 保持 `NOT_IMPLEMENTED`（笔刷切换/加载不在 D6-1 范围）。
- modeler 参数是**context 级单例 predictor**（每个 context 一个），与具体笔刷无关：modeler settingId 路径仍校验 `brush != DGC_INVALID_BRUSH`（保持 C ABI 语义一致），但实际落到 context 级 predictor，忽略句柄具体值；4 个笔刷内核 settingId（0-3）维持现状「存参不作用于默认笔刷」（D6-1 不要求接通 RADIUS/HARDNESS/OPACITY）。

### 4.5 映射清单文档

新增 `docs/brush_settings_mapping.md`（SDK 仓库），一张表覆盖 9 个 modeler 参数 + 既有 4 项：参数名 ↔ settingId ↔ 默认值/单位 ↔ 消费端滑杆建议范围。默认值取自 `StrokeModelParams` 字面默认值。

## 8. 风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 惰性注入前引擎已 `start()`，`predictor_` 写入与 `inputLoop` 读并发 | 数据竞争/UB | `predictor_mutex_` 加锁注入 + `inputLoop` 加锁读（§4.3）；predictor 注入后不替换不销毁 |
| R2 | `Configure()` 内部 `Reset()` 与 `inputLoop` 的 `Update/Predict/Reset` 并发 | 状态撕裂/输出不可复现 | `StrokeModeler::Impl` 内部 `std::mutex`；生产约定「笔画之间改参」 |
| R3 | 误把 predictor 默认接入导致 golden PNG 逐字节 diff 失败 | 违反零回归验收 | 采用惰性激活，`dgcCreate` 不注入（§4.2） |
| R4 | `dgcCreateBrush` 语义从 NOT_IMPLEMENTED 变有效句柄，与 B3-1 R4「不作用于默认笔刷」冲突理解 | 评审误解 | 文档明确：句柄仅做发号器供 `dgcSetBrushSetting/Color` 校验；`dgcSetBrush/dgcDestroyBrush` 仍 NOT_IMPLEMENTED；modeler 参数 context 级、不按笔刷分 |
| R5 | `DGC_SETTING_COUNT` 扩为 13 后 `Impl::brush_settings` 数组维度与枚举失配 | 编译/越界 | `brush_settings` 用 `std::array<double, DGC_SETTING_COUNT>` 自动跟随；编译 + sanitize 兜底 |
| R6 | paint-pc submodule 未更新到含新枚举的 SDK commit | 消费端编不过（未知枚举名） | 执行时先让 paint-pc submodule 指向含 D6-1 的 SDK（合 main 或临时指分支），见 §5.2 边界说明 |
| R7 | modeler 参数只作用于「新笔画」，用户在笔画中途拖滑杆 | 当前笔画无变化（符合「对新笔画生效」） | 面板在 `strokeActive==false` 才提交设置；任务书允许「对新笔画（或实时）生效」 |

## 9. SDK 工程约束（必含）

- **所有权/RAII**：predictor 一律 `std::make_unique<StrokeModeler>()` 创建、经 `Engine::setPredictor(std::unique_ptr<StrokeModeler>)` 移交，最终由 `Engine::predictor_`（`unique_ptr`）析构；`DgcContext::Impl::predictor_handle_` 为**非拥有裸指针**（不 `new` 不 `delete`，仅作 `Configure` 入口）；`next_brush_handle_` 为值成员。全程零裸 `new/delete` 所有权。
- **Pimpl 边界**：`StrokeModelParams`/`StrokeModeler` 属 `core/` 内部，不进 C ABI；对外唯一头 `dgc_paint_c_api.h` 只增纯 C 枚举值（`int`/`DgcBrush`），`DgcContext` 仍为不透明句柄。内部实现类型不暴露给消费者。
- **泄漏验证**：`DGCPAIN_SANITIZE=ON`（`host-linux-sanitize` preset，ASan+LSan）跑 `ctest`，LSan 零报告；新增「createBrush→setBrushSetting(modeler)→destroy」循环覆盖 predictor 注入/释放路径（`core/engine` 的 `predictor_` unique_ptr 析构释放、`predictor_handle_` 不重复释放）。
