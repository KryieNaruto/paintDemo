## 目标

把 dab 形状光栅化从 CPU（`MakeSoftCircleStamp` 逐 dab 烘焙 RGBA 位图 + staging 上传成 stamp 纹理）搬到 GPU compute，复刻画世界 §3.2「SDF 覆盖 + fwidth 抗锯齿」算法骨架，并与既有 B2-1 `brush_composite.comp` 的「premultiplied over」合成**融合成一个 pass**（路线 B §2.1/§9 推荐的融合形态一）。参数层（间距/压力曲线/抖动/HSV 调制）仍留 CPU（B3-1 `kernels/brush/` 不变），只搬「形状 → 覆盖」这一段。

具体产出（对齐任务书 §B4-1「产出」）：

1. `brush_composite.comp` 演进为「内联形状光栅化 + over 合成」融合版：
   - push_constant 从 `stampPos/stampSize/opacity/alphaLock` 扩为 `pos/radius/hardness/softness/opacity/rgb/shapeType`。
   - shader 内对画布像素做圆形 SDF 覆盖：`distToCenter = distance(pixelCoord, pos)`，`ww = fwidth(distToCenter)`，`smoothstep` 抗锯齿，再叠加 hardness/softness 软硬边（对齐 §3.2 圆形公式 + B3-1 `MakeSoftCircleStamp` 的 `hardness→edge→smoothstep` 语义）。
   - 不再上传 stamp 纹理：移除 per-dab `CreateStampTexture` + `vkCmdCopyBufferToImage` 上传路径（staging buffer 随 stamp 纹理一并移除）。
   - `shapeType` 位预留（0=圆形软笔，默认；1=方形/2=椭圆/3=空心为扩展位，本期不实现）。
2. CPU 参考保留：`MakeSoftCircleStamp` 从 `vk_backend.cpp` **挪进测试侧**作对照 oracle（diff 测试的独立基准）。
3. 确定性对照测试（新增 ctest）：同一组 `StampData`，CPU 参考 vs GPU 光栅化做像素级 diff（容差 ≤ 8/255）。双证：① 对照 diff；② B5-3 同 seed 两次 PNG 像素一致回归保持绿。

## 技术方案

### 现状（B2-1/B3-1）

- `vk_backend.cpp::MakeSoftCircleStamp`：对每个 `StampData` 逐像素烘焙 `d×d`（`d=ceil(2*radius)`）软圆 RGBA 位图（hardness/softness → `edge = hardness*(1-softness)`，`dist<=edge` 全 alpha，`edge<dist<1` 走 `smoothstep` 斜坡，颜色取 `s.r/g/b`）。
- `CompositeLocked()`：每 dab 一次 `MakeSoftCircleStamp` → `CreateStampTexture(size)` → staging map/memcpy → `vkCmdCopyBufferToImage` 上传 → transition → bind pipeline → 填 push constant（stampPos/stampSize/opacity/alphaLock）→ **全画布 dispatch**（shader 内 uv 裁剪只写包围盒）→ `SubmitAndWait`。
- `brush_composite.comp`：`binding0 = image2D u_Canvas`，`binding1 = sampler2D u_Stamp`，采样 stamp 后 `out = src.rgb*a + dst.rgb*(1-a), a+dst.a*(1-a)`。

### 目标形态

融合版 shader 一个 pass 完成「形状 SDF → 覆盖 → over 合成」，去掉 stamp 纹理 + sampler + staging 三个资源。

覆盖公式（执行时微调，保证与 CPU 参考 diff 在容差内）：

```glsl
// 归一化距离：0 = 圆心，1 = 半径边缘
float dist = length(pixelCenter - pc.pos) / max(pc.radius, 1e-3);

// hardness/softness 软硬边（对齐 MakeSoftCircleStamp 的 edge 语义）
float edge = pc.hardness * (1.0 - pc.softness);
float coverage = (dist <= edge) ? 1.0
                               : (1.0 - smoothstep(edge, 1.0, dist));

// §3.2 fwidth 抗锯齿：仅在外缘 rim（dist 穿越 1.0）补 1px 过渡
float ww = fwidth(dist);                     // 见风险 R1（derivative 支持）
float rimAA = 1.0 - smoothstep(1.0 - ww, 1.0 + ww, dist);
coverage *= rimAA;

float a = coverage * pc.opacity;
if (a <= 0.001) return;
vec4 dst = imageLoad(u_Canvas, c);
vec4 outC = vec4(vec3(pc.r, pc.g, pc.b) * a + dst.rgb * (1.0 - a),
                 a + dst.a * (1.0 - a));
imageStore(u_Canvas, c, outC);
```

- 硬核区（`dist<=edge`）与 CPU 参考逐位一致；软边斜坡（`edge→1`）与 CPU `smoothstep` 语义一致；fwidth 仅在 rim 补亚像素 AA，微差由 diff 容差 ≤8/255 吸收。
- 包围盒 dispatch：`gx = ceil(2*radius / 8)`、`gy = gx`（以 `pos` 为中心的包围盒，落点 `pos-radius`），替代全画布 dispatch；全画布 dispatch 作为简单回退（shader 内 `dist` 越界早退）亦可。

### push_constant 布局（对齐陷阱规避）

`vec3` 在 push constant（std140 语义）有 16 字节对齐陷阱，故用 **flat `float rgb[3]`**，C++ struct 与 GLSL 逐字段一致：

```glsl
layout(push_constant) uniform PC {
    vec2  pos;          // dab 圆心（画布像素）
    float radius;       // 半径
    float hardness;     // 硬核 0..1
    float softness;     // 外缘软化 0..1
    float opacity;      // dab 不透明度
    float rgb[3];       // straight RGB（0..1）
    uint  shapeType;    // 0=圆形（默认），1/2/3 扩展位
} pc;
```

```cpp
struct BrushPushConstant {
    float pos[2];
    float radius, hardness, softness, opacity;
    float rgb[3];
    std::uint32_t shapeType;
};
static_assert(sizeof(BrushPushConstant) == 10 * sizeof(float), "push constant size");
```

合计 40 字节，4 字节自然对齐无 padding，远低于 Vulkan 128B 保底。

### CPU/GPU 像素对照验证方式

新增 `tests/test_gpu_dab_raster.cpp`（Vulkan 开时注册），对一组覆盖不同 `radius/hardness/softness/opacity/rgb` 的 `StampData`：

1. 每个 dab：`VkBackend initOffscreen(W,H)` → `clearCanvas()`（白底）→ `composite({s})` → `readback` 得 GPU 画布。
2. 同 dab：CPU 参考从同一白底画布出发，用测试侧 `MakeSoftCircleStamp` + 相同 `over` 公式合成进缓冲得 CPU 画布。
3. 逐像素 diff：`max|gpu - cpu| ≤ 8`（8/255），且断言「中心变暗 + 包围盒外保持白底」双证笔迹可见。
4. 确定性回归由既有 `test_determinism`（B5-3）保证，本测试不重复测 seed。

> CPU 参考的 `over` 公式必须与 GPU 一致（`out.rgb = srcRGB*a + dst.rgb*(1-a); out.a = a + dst.a*(1-a)`），否则 diff 无意义。参考实现独立于 `vk_backend.cpp`，避免「拿被测代码当 oracle」的同源问题。

## 步骤

### 1. 融合版 shader + push constant（`brush_composite.comp` + `vk_backend.cpp`）

1. 改 `.comp`：删 `u_Stamp` binding、改 push constant、实现 SDF 覆盖 + fwidth AA + hardness/softness 边 + over 合成。
2. 改 `BrushPushConstant` + `static_assert`。
3. `EnsureDevice()`：descriptor layout 从 2 binding 减为 1（STORAGE_IMAGE）；push constant range size = `sizeof(BrushPushConstant)`；删除 sampler 创建。
4. `CreateCanvas()`：descriptor pool 从 2 pool size 减为 1；`vkUpdateDescriptorSets` 只写 binding 0。
5. 删除 stamp/staging 成员与 `CreateStampTexture`/`DestroyStampTexture`（RAII 守卫 `.reset()` 幂等，直接删即释放）。

### 2. `CompositeLocked()` 去烘焙 + 包围盒 dispatch

1. 去掉 `MakeSoftCircleStamp`/`CreateStampTexture`/staging 上传/transition 代码块。
2. 填新 push constant（`pos=s.x,s.y`、`radius=s.radius`、`hardness`、`softness`、`opacity`、`rgb=s.r/g/b`、`shapeType=0`）。
3. dispatch：`gx=gy=ceil(2*radius/8)`，落点 `pos - radius`（或全画布回退）。

### 3. CPU 参考挪测试侧（`tests/cpu_stamp_reference.h`）

1. 把 `MakeSoftCircleStamp` 从 `vk_backend.cpp` 迁移为测试侧 `inline` 函数（逻辑不变）。
2. 加 `CompositeOverCpu(canvas, StampData)`：白底画布 + 与 GPU 一致的 `over` 合成。

### 4. 对照测试（`tests/test_gpu_dab_raster.cpp` + `tests/CMakeLists.txt`）

1. 一组 `StampData`（大/小半径、硬/软、有/无 softness、彩色/黑）：逐 dab `composite({s})` → readback → 与 CPU 参考 diff ≤ 8/255 + 笔迹可见断言。
2. `shapeType=0` 默认圆形断言（硬核中心、包围盒外白底、圆形对称）。
3. 多轮 `initOffscreen→composite→readback→shutdown` 泄漏循环（供 ASan/LSan）。

## SDK 工程约束落点（RAII / Pimpl / 零泄漏）

- **所有权设计（谁拥有）**：`VkBackend::Impl` 继续用既有 `VkTopHandle`/`VkDeviceHandle` RAII 守卫（值语义、禁拷贝、可移动、`reset()`/析构幂等）持有全部 Vulkan 句柄；删除 stamp/staging 成员即自动释放，**不新增任何裸 `new/delete` 所有权**。测试侧 CPU 参考只用 `std::vector<uint8_t>`（值语义），无所有权负担。
- **Pimpl 边界**：`VkBackend` 保持经典 Pimpl（`std::unique_ptr<Impl> impl_`，`Impl` 定义留 `.cpp`）；本次改动全落在 `Impl` 与 `.comp`，`vk_backend.h` 与 `i_render_backend.h` 的对外 ABI 面不变，C ABI（`dgc_paint_c_api.h`）不暴露任何 Vulkan/内部类型。
- **泄漏验证方式**：`DGCPAIN_SANITIZE=ON` host 构建（ASan + LSan）跑 `test_gpu_dab_raster` 的多轮 init/composite/readback/shutdown 循环 + 既有 `test_ownership_loop`，CI 断言零泄漏。

## 风险

| # | 风险 | 影响 | 缓解 / 决策 |
|---|---|---|---|
| R1 | **`fwidth` 在 compute shader 需 derivative 支持**（`GL_ARB_derivative_control` / SPV `DerivativeControl` / NV compute derivatives），lavapipe 或 Android 可能不支持 | 编译失败或 AA 缺失 | 执行起点先探测 lavapipe 对 compute derivative 的支持；不支持则用**解析 AA 宽度兜底** `ww = 1.0 / max(radius, 1.0)`（归一化下 1px 带宽，等价软边），仍满足「SDF+AA 覆盖」，diff 容差吸收差异；两路径（shaderc/glslc）编译 flag 同步 |
| R2 | **软边模型差异**：CPU `smoothstep(edge,1,dist)` 软边宽 = `(1-edge)*radius` 像素，fwidth 仅 ~1px | diff 测试在软边超容差 | GPU 以 `hardness/softness edge` 为**主覆盖**（与 CPU 逐位一致），fwidth 仅 rim 补 AA；diff 容差 ≤8/255 覆盖；硬核区逐位一致是强断言 |
| R3 | **B5-3 golden PNG 逐字节校验失败**：光栅化输出变化 → `golden_determinism.png` 不再匹配 | `test_determinism` 红 | 实现后重跑 `tests/fixtures/regenerate_golden.sh` 重建 golden；「同 seed 两次 memcmp 一致」部分不受影响，仍绿（确定性回归主验收保住） |
| R4 | **push constant 对齐陷阱**：GLSL `vec3` 在 push constant（std140 语义）16 字节对齐会插 padding | C++/GLSL 布局错位 | 用 flat `float rgb[3]`，逐字段对齐 + `static_assert(sizeof==40)` |
| R5 | **descriptor set/pool 计数错配**：删 stamp binding 后 layout/pool/update 三处不一致 | validation error | layout/pool/update 三处同步减为单 binding；写 descriptor 只写 binding 0 |
| R6 | **Android glslc 预编译路径**：改 `.comp` 后需重跑 cmake 重生成 SPIR-V；若引入扩展需额外 glslc flag | Android `.so` 编不出 | 重跑 `--preset android-arm64`；无 NDK 时 host 通过即可（任务书明示） |
| R7 | **观感回归**（U2 已记录 dgcClear 恒清白类） | 笔迹异常 | 不碰 `clearCanvas`；依赖 `test_brush_offscreen`/`test_offscreen`/`test_determinism` 保持绿；核心/硬核区 diff 逐位断言兜底 |
