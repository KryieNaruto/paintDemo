# E0-2 · 一键脚本 `setup-env.sh` 实施计划

> 任务线：线0-环境 · 换机后快速搭建工具链。状态/审核 SOT 见 `docs/tasks/任务线.md`，本计划不改。
> 依据：`docs/tasks/detail/环境搭建与项目骨架.md` E0-2；`DGCPaint_技术规划.md` §1、§2；`docs/env/env-setup.md`（E0-1 已交付，其 §1 探测清单为本脚本「单一事实来源」）。

## 目标

`scripts/setup-env.sh` 一条命令换机搭环境：自动探测 cmake / ninja / C++ 编译器 / NDK / Vulkan，硬依赖缺失提示并按 E0-1 说明书补缺（Linux 可尝试 `apt install`，需 sudo 时声明），软依赖缺失仅警告不失败。提供 `--check` 只探测不安装。

## 验收标准（抄自 `docs/tasks/detail/环境搭建与项目骨架.md` · E0-2）

- 缺编译器时非零退出并给安装指引；仅缺 NDK/Vulkan 时 0 退出并警告。
- `--check` 输出缺项清单，与 E0-1 文档一致。
- 不创建 SDK CMake 工程。

（任务书「产出」还要求：探测 cmake/ninja/C++ 编译器；缺则提示按 E0-1 说明书安装，Linux 可尝试自动 `apt install` 并声明需 sudo；NDK/Vulkan 有则打印版本、无则警告不失败。）

## 脚本设计

### 探测清单（与 `docs/env/env-setup.md` §1 表逐项对齐，硬/软级别一致）

| 检查项 | 探测方式 | 级别 | 版本下限（有则校验并打印） |
|---|---|---|---|
| cmake | `command -v cmake` → `cmake --version` | 硬 | ≥ 3.22（建议 3.31+，只校验下限 3.22） |
| ninja | `command -v ninja` → `ninja --version` | 硬 | 较新即可（不校验具体版本） |
| C++ 编译器 | `command -v g++` → `g++ --version`（Linux） | 硬 | GCC ≥ 11 |
| Vulkan | `command -v vulkaninfo`（Linux） | 软 | 有则打印，无则警告 |
| NDK | `$ANDROID_NDK_HOME` 非空且目录存在 | 软 | r27+（建议 r28）；可从 `$ANDROID_NDK_HOME/source.properties` 读 `Pkg.Revision`，读不到则只打印路径 |
| glslc | `command -v glslc` → `glslc --version` | 软 | 有则打印，无则警告 |

> 硬/软边界依据同 E0-1：以「Null 后端不硬依赖」为准，NDK、Vulkan、glslc 一律软依赖、仅警告。

### 模式与退出码

- **默认（安装）模式**：
  - 先探测全部项。
  - 硬依赖缺失 → Linux（Debian/Ubuntu 系，检测 `apt-get` 存在）尝试 `sudo apt-get install -y build-essential cmake ninja-build`，需 sudo 时在输出中**明确声明**；非 apt 系统或用户拒绝 sudo → 打印 E0-1 说明书对应小节指引（`docs/env/env-setup.md` §2.2/§2.4）并**非零退出**。
  - 仅软依赖缺失 → 打印 WARN + 补缺提示（Vulkan→`libvulkan-dev`、NDK→r27+/r28 路径、glslc 随 NDK/Vulkan SDK），**0 退出**。
  - 全部就绪 → 打印各版本汇总，0 退出。
- **`--check` 模式**：只探测不安装，逐项输出「OK / MISS(硬) / WARN(软)」缺项清单；硬依赖缺 → 非零退出（exit 1），仅软依赖缺 → 0 退出。输出口径与 `docs/env/env-setup.md` §1 一致。
- **`--help` / `-h`**：打印用法（`setup-env.sh [--check]`）后 0 退出。
- 脚本头部 `#!/usr/bin/env bash` + `set -euo pipefail`；探测命令（可能失败者）统一 `command -v ... >/dev/null 2>&1 || ...`，不得被 `set -e` 误触发中断。

### Windows 处理

脚本是 bash，主战场 Linux host。检测到 `uname -s` 非 Linux（MINGW/MSYS）时不自动探测 `cl.exe`（需在「Developer Command Prompt for VS 2026」内），改为打印 E0-1 §3 的手动步骤指引后退出。跨平台自动安装不属本任务范围。

## 步骤

1. 建 `scripts/` 目录，写 `scripts/setup-env.sh`，按「脚本设计」实现：参数解析（`--check`/`--help`）、探测函数（`has()` + 版本解析）、硬/软依赖分级、默认安装与 `--check` 两分支、退出码。
2. 版本下限解析：cmake 解析 `cmake --version` 首行数字并与 3.22 比较；g++ 解析主版本号并与 11 比较；NDK 尝试读 `source.properties` 的 `Pkg.Revision`。解析失败不误判为「缺」，回退为「有但版本无法确认」并提示。
3. 缺项指引文案直接引用 `docs/env/env-setup.md` 的小节（§2.2 Linux 安装、§2.4 补缺、§3 Windows、§0 硬/软分级），保证与 E0-1 口径一致。
4. `chmod +x scripts/setup-env.sh`。
5. 自检（对照验收三条）：
   - 临时 PATH 屏蔽 g++（`env PATH=<不含编译器>` 或 `command -v g++` 返回空）验证硬缺时非零退出 + 安装指引；屏蔽 NDK/Vulkan 验证仅软缺时 0 退出 + 警告。
   - `./scripts/setup-env.sh --check` 输出缺项清单，与 `docs/env/env-setup.md` §1 表逐项对照。
   - 确认未新增 `CMakeLists.txt`（`git status` 只应有 `scripts/setup-env.sh`）。

## 风险

- **口径漂移**：`--check` 清单与 E0-1 文档不一致会被打回。以 `docs/env/env-setup.md` §1 为唯一事实来源，逐项复制级别与命令，不改其措辞。
- **`set -e` 误中断**：探测命令天然会失败（缺项时 `command -v` 返回非零），未用 `||` 兜住会直接退出。所有「预期可能失败」的探测统一 `|| true` / `2>/dev/null || ...` 包裹。
- **硬/软边界误判**：把 NDK/Vulkan 标为硬依赖会阻断 Null 后端 host 编译。严格按 E0-1：NDK/Vulkan/glslc 一律软依赖。
- **sudo 越权/交互卡死**：自动 `apt install` 需 sudo，应声明「将尝试使用 sudo」并允许 `--check` 或非交互环境跳过（无 sudo/非 apt 时降级为打印指引 + 非零退出），避免脚本静默挂起或擅自提权。
- **版本解析脆弱**：不同发行版 `cmake --version`/`g++ --version` 输出格式略有差异，解析需容错，解析失败回退为「有但无法确认版本」而非「缺失」。
- **越界**：不得顺手补 CMake 工程文件或消费者代码，保持单一脚本交付。
