## 步骤（全部在 worktree；探测在 WSL Ubuntu）

Windows 上用 `python`。bash 脚本可在 Git Bash / 编辑器里写；**apt 与 `check-env.sh` 实测必须在 WSL Ubuntu 里跑**。

Worktree 在 WSL 中的路径（空格必须加引号）：

```text
/mnt/d/qsw/canvas demo/paintDemo/.worktrees/E0-2
```

### 1. 安装 WSL Ubuntu（本机）

在 Windows PowerShell（优先管理员）执行：

```powershell
wsl -l -v
```

- 已有 **Ubuntu**（或 Ubuntu-22.04 / 24.04）且状态 Running / Stopped：跳过安装，进入第 2 步。
- 没有任何发行版：安装 Ubuntu。建议 22.04+（apt 的 cmake 才稳过 3.22；20.04 默认 cmake 过旧）。

```powershell
wsl --install -d Ubuntu
```

若系统提示重启：重启后再打开 Ubuntu 完成首次用户名/密码（此步可能需人交互）。execute 不得在未完成发行版时假装探测通过。

WSL 安装后确认：

```powershell
wsl -d Ubuntu -- uname -s
# 期望：Linux
```

### 2. 在 Ubuntu 里 apt 四包

进入发行版后（对 worktree 仓库根，或任意目录均可装包）：

```bash
sudo apt update
sudo apt install --no-install-recommends build-essential cmake ninja-build libvulkan-dev
```

说明写进 `linux-host.md`，与任务书包名一致，**不要加减 glfw**：

- **`build-essential`**：提供 `g++`（及 `make`）；验收看的是 `g++`。
- **`cmake`**：发行版包须 ≥ 3.22；若 `cmake --version` 过旧，文档写 Kitware 源或官方二进制升到 3.22+（规划建议 host 独立装 3.31+，探测门禁仍 3.22）。
- **`ninja-build`**：Debian 包名；二进制可能是 `ninja`（`check-env.sh` 已试 `ninja` 再 `ninja-build`）。
- **`libvulkan-dev`**：提供 `/usr/include/vulkan/vulkan.h` 与 pc 文件；**无 GPU / 无 ICD 不视为失败**（任务书原文）。

`pkg-config`：任务书允许用它发现 Vulkan 头；`libvulkan-dev` 通常会带上头文件。文档可写「若要用 `pkg-config --exists vulkan`，再装 `pkg-config`」。**不要**把 `pkg-config` 写成 glfw 一类的必需消费者包；也**不要**把它漏写成第五个「任务书四包」替代项。四包名单不得改。

**明确不装**：`libglfw3-dev`、JDK、Android Studio。GLFW 属 `paint-pc` 消费者。

非 Ubuntu（Fedora/`dnf`、Arch/`pacman`）可在文档各给一行等价包名，**本机验收路径仍是 WSL Ubuntu + apt 四包**。

### 3. 在 WSL 对 worktree 跑探测

```bash
cd "/mnt/d/qsw/canvas demo/paintDemo/.worktrees/E0-2"
bash scripts/check-env.sh
```

期望：

- 整体 **exit 0**
- `g++`（或脚本打印的 `cxx`）/ `cmake`（≥3.22）/ `ninja` 为 **OK**
- Vulkan 为 **OK**（`pkg-config vulkan` 或找到 `vulkan/vulkan.h`）。落地四包后不应再 WARN Vulkan。
- NDK 可 WARN（E0-3）
- 不得因无 GLFW 失败

Vulkan 验收只探头文件 / `pkg-config`。不要用「能否创建 VkInstance / 有无 GPU」当失败。

不要在这一步执行 `cmake --preset`、不要编译 `core/`、不要创建工程文件。

### 4. 写 `docs/env/linux-host.md`

面向 Debian/Ubuntu（含 **WSL Ubuntu**）。内容至少包括：

- 任务书四包的 `apt update` + `apt install` 命令（与第 2 步相同）。
- Windows 开发者：用 WSL Ubuntu；worktree 走 `/mnt/<盘符>/...`；路径含空格必须加引号。
- 装完在仓库根执行 `bash scripts/check-env.sh`，期望与第 3 步一致。
- 无 GPU 运行时不视为失败。
- **不做**：`cmake --preset`、编译 `core/`、创建 `CMakeLists.txt`（B1-2）。
- 指向 [`docs/env/toolchain.md`](../env/toolchain.md) 作为版本数字 SOT，本文只写 **怎么装**。
- 声明 `setup-linux-host.sh` 需要 sudo（若采用第 5 步）。

### 5. 建议写 `scripts/setup-linux-host.sh`

风格对齐 `check-env.sh` / `bootstrap-consumer.sh`：`#!/usr/bin/env bash`、`--help`、中文说明。

- 开头声明：**需要 sudo**；拒绝在非 Linux 上跑（`uname -s` 不是 Linux 则打印「请到 Linux 或 WSL 执行」并**非零退出**）。不要在 Windows/Git Bash 里调用 `apt`。
- 只安装任务书四包；**禁止**出现 `libglfw3-dev` / `glfw`。
- 装完可调用同仓库 `scripts/check-env.sh`，把探测结果打到 stdout。
- 可执行位：Windows worktree 用 `git update-index --chmod=+x`。

### 6. 改 README §5.1 与 `toolchain.md` 链接

- §5.1 保留 apt 一行，并链到 [`docs/env/linux-host.md`](docs/env/linux-host.md)；说明完整步骤、WSL 路径与「无 GPU 不算失败」在该文件。
- `toolchain.md` 把「将写 `linux-host.md`」改成已落地链接。

### 7. 自检清单（留给 execute / test）

1. git diff **没有** 仓库根 `CMakeLists.txt` / `CMakePresets.json`，没有 `ui/` `platform/` `app/`，没有对 `core/` 的编译。
2. 安装文档与脚本 **都不包含** `libglfw3-dev`。
3. 在 WSL Ubuntu 对 **本 worktree** 跑过 `check-env.sh`：**exit 0**；行内有 cmake≥3.22、ninja、g++；Vulkan 为 OK。
