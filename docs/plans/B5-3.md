## 目标

B5-3 是**纯验证/测试任务**，不改 `dgc_paint` 库语义，只补「确定性渲染」的端到端证明：把 B1-7（机制级同 seed 同序列）与 B3-1（内核 dab 真实产出）串起来，在 host 离屏链路上证明**同一脚本（同 C API 调用序列）同 seed 两次运行，产出的 PNG 像素级一致（逐字节 diff = 0）**，并落地 golden PNG 逐字节 diff（§4.0.3 / §阶段7）。

具体：

1. **C API 级端到端确定性**：`test_determinism.cpp` 内，同 seed 两次 `dgcCreate → dgcSetOffscreenSurface → dgcClear → dgcSetRandomSeed/dgcSetFixedTime → dgcBeginStroke/dgcStrokeTo…/dgcEndStroke → dgcFlush → dgcReadbackPixels`，两次 readback 缓冲 `memcmp` 全零（像素级一致）。
2. **golden PNG 逐字节 diff**：同一规范序列经 `dgcExportPNG` 两次导出，两次 PNG 文件逐字节一致；并与提交的 `tests/fixtures/golden_determinism.png` 逐字节 diff = 0。
3. **脚本级（CLI）两次运行一致**：`test_cli.cpp` 增一条「同脚本同 seed 两次 `dgc_cli run` → 两个 PNG 逐字节一致」，字面落 §阶段7「同脚本同 seed 两次运行 PNG 像素级一致」。
4. **规范确定性脚本 fixture**：新增 `tests/fixtures/determinism_script.json`（canvas + seed + fixed-time + 纯 stroke + export，不含 `load-brush/set-brush/set-color/set-param/undo`，避免 `NOT_IMPLEMENTED`/`INVALID_HANDLE` 噪声），既是 golden 生成源，也是 test_cli 两次运行的输入。

非目标：不改 `ui/` `platform/` `app/`；不改 `dgc_paint` 库任何 `.cpp/.h`（纯测试 + fixture）；不做「不同 seed 产出不同像素」的断言（当前默认笔刷 `offset_by_random=0`、`random_input` 返回值被丢弃，seed 不改变像素，见风险 R2）；不做 AI 侧像素对比（§4.0.6「对比模式不在 CLI 范围」）；不验证窗口 `present` 路径（本仓库离屏 only）。

## 验收标准（人工授权派生，非任务书原文）

依据 §4.0.3 + §阶段7：

1. **同 seed 两次运行像素级一致（§阶段7）**：host 离屏下，同 seed 两次走同一 C API 序列（或同一脚本），两次 `dgcReadbackPixels` 读回缓冲 `memcmp == 0`；经 `dgcExportPNG` 两次导出的 PNG 文件**逐字节 diff = 0**。
2. **golden PNG 逐字节 diff（§4.0.3）**：`test_determinism` 用规范序列导出 PNG，与提交的 `tests/fixtures/golden_determinism.png` **逐字节一致**（`memcmp` 全文件）。
3. **脚本级两次运行一致（§阶段7「同脚本同 seed 两次运行 PNG 像素级一致」）**：`test_cli` 对 `determinism_script.json` 两次 `dgc_cli run --out`，两 PNG 逐字节一致。
4. **离屏可用性降级**：无 Vulkan（Null 后端 / `supportsOffscreen()==false`）时，确定性/golden 相关断言**跳过并打 SKIP 标记**，机制级断言（B1-7 a–e）仍通过；不因缺 Vulkan 而整测失败（同 `test_cli` 口径）。
5. **golden 可再生成**：提供一键再生成路径（脚本或 `DGCPAIN_REGENERATE_GOLDEN` 环境变量），换机/换驱动后按 §4.0.3「跨 GPU ±1 LSB 容差」重建 golden，不回退测试（见风险 R3）。
6. **测试**：`test_determinism` 扩后通过；`test_cli` 扩后通过；既有 ctest 全绿（`compile_null`/`test_ring_buffer`/`test_engine`/`test_c_api_header`/`test_c_api_b1_6`/`test_offscreen`/`test_brush_kernel`/`test_brush_offscreen`/`test_ownership_loop`/`test_stroke_predictor`/`test_cli`）。
7. **所有权 / Pimpl（SDK 约束，测试侧）**：B5-3 不改 `dgc_paint` 库，库内既有无裸 `new/delete` 所有权不变；新增测试代码只经 `dgc_paint_c_api.h`（公开头）驱动渲染，**不 include `render/` `kernels/` 内部头**、不触碰 `DgcContext` 内部；所有 `DgcContext*` 生命周期用 RAII 守卫（`unique_ptr` + `dgcDestroy` 自定义 deleter）配对 create/destroy，无裸 `delete`。
8. **泄漏验证**：`DGCPAIN_SANITIZE=ON`（ASan/LSan）下 `ctest` 零报告（`test_determinism` 新增段 create/destroy 配对；离屏段在 lavapipe 下同机运行，复用 B2-1/B3-1 已验证的 VkBackend RAII 关闭路径）。

## 所有权设计 / Pimpl 边界 / 泄漏验证（SDK 工程约束）

### 所有权（谁拥有、RAII、零裸 new/delete）

- **`dgc_paint` 库内改动 = 0**：B5-3 是纯测试任务，不新增任何库内对象所有权；既有 `DgcContext::Impl` 的 `kernel/backend/engine/rng` 全 `unique_ptr`、声明序析构不变。
- **测试侧**：`test_determinism.cpp` 新增段的 `DgcContext*` 用 RAII 守卫（`std::unique_ptr<DgcContext, decltype(&dgcDestroy)>`，或等价 `CtxGuard`，同 `cli/script_runner.cpp` 先例），异常/提前返回均自动 `dgcDestroy`，**禁止裸 `delete`/手动 `dgcDestroy`**；readback 缓冲用 `std::vector<uint8_t>`；PNG 内容用 `std::vector<uint8_t>`/`std::ifstream` 读入比较，无裸堆所有权。

### Pimpl 边界（对外 ABI 面经不透明句柄隐藏实现）

- 新增测试段**只** `#include "dgc_paint_c_api.h"` 驱动端到端渲染（离屏/确定性/readback/exportPNG 全部公开 C API）；**不 include** `render/vulkan/*`、`kernels/brush/*`、`core/engine.h` 内部头（现有 `test_determinism.cpp` 为白盒机制测试已 include `core/determinism.h`，那一段保留不动，新增渲染段不越过 C API 边界）。
- `DgcContext` 仍是 `typedef struct DgcContext DgcContext;` 不透明句柄；测试无从访问 `Impl`。
- golden fixture（`.png` / `.json`）为纯数据文件，不引入任何 ABI 面。

### 泄漏验证方式

- **静态**：B5-3 无库内改动，无需重跑全库 `grep new/delete`；新增测试源码自查无 `new`/`delete` 所有权（仅 RAII 守卫 `make_unique`）。
- **动态（ASan/LSan）**：`cmake --preset host-linux-sanitize && cmake --build`，`ctest --test-dir build/host-linux-sanitize --output-on-failure`，重点 `test_determinism`、`test_cli`、`test_ownership_loop`，要求零报告。离屏段每轮 create/destroy 配对，`VkBackend` 在 `dgcDestroy` 走 RAII `shutdown()`（B2-1 已证无泄漏）。
- **注意**：lavapipe/Vulkan loader 自身分配在 LSan 下可能产生噪声（B2-1/B3-1 已同机验证过可零报告）；若遇 loader 误报，golden/离屏断言在 sanitize 构建下可沿用「跳过离屏段、保留机制段」的口径，并在 PR 标注（见风险 R4）。

### 1. 规范脚本 fixture（`determinism_script.json`）

```json
{
  "canvas": { "w": 128, "h": 128, "background": [1, 1, 1, 1] },
  "seed": 42,
  "fixed-time": 1000000,
  "ops": [
    { "op": "stroke", "points": [
```

### 3. 扩展 `test_determinism.cpp`

在既有机制段（a–e）之后追加：

```cpp
#include <cstring>
#include <fstream>
#include <memory>
#include <vector>
#include "dgc_paint_c_api.h"   // 已有

// 离屏能力探测（复用 test_cli 思路）
static bool offscreenAvailable() { /* dgcCreate → dgcSetOffscreenSurface(64,64) → dgcDestroy */ }

// 一次端到端渲染：建 ctx → offscreen → clear → seed/fixed-time → stroke → flush → readback
static void renderOnce(std::vector<uint8_t>& out, uint64_t seed, double fixedTime) {
    using CtxGuard = std::unique_ptr<DgcContext, decltype(&dgcDestroy)>;
    CtxGuard ctx(dgcCreate(), &dgcDestroy);
    dgcSetOffscreenSurface(ctx.get(), 128, 128);
    dgcClear(ctx.get(), 1,1,1,1);
    dgcSetRandomSeed(ctx.get(), seed);
    dgcSetFixedTime(ctx.get(), fixedTime);
    dgcBeginStroke(ctx.get(), 16,16, 0.5f, 0,0);
    dgcStrokeTo(ctx.get(), 64,64, 0.7f, 0.2f,-0.1f, 0);
    dgcStrokeTo(ctx.get(), 112,112, 0.9f, 0.3f,-0.2f, 0);
    dgcEndStroke(ctx.get());
    dgcFlush(ctx.get());
    out.assign(128*128*4, 0);
    dgcReadbackPixels(ctx.get(), out.data());
}
```

断言：
1. **同 seed 两次 readback `memcmp==0`**（§阶段7 像素级一致，主验收）。
2. **不同 seed 两次 readback 相等与否不强断言**（默认笔刷 seed 不影响像素，见风险 R2；只记录 `fprintf` 观察值，不 CHECK）。
3. **golden 导出**：`renderOnce → dgcExportPNG` 两次到 `/tmp`，读回两文件逐字节 `memcmp==0`；再与 `DGC_FIXTURE_DIR/golden_determinism.png` 逐字节 diff（若 fixture 缺失 → SKIP + 提示先跑步骤 2）。
4. 离屏不可用时整段 SKIP（`fprintf("[test_determinism] SKIP offscreen/golden ...")`），机制段仍通过。

## 风险与备选

1. **验收来源缺失（已声明）**：`docs/tasks/detail/` 无 B5-3 任务书，本计划验收为人工授权派生（依据 §4.0.3 + §阶段7 权威原文）。执行前若需正式任务书，先补 detail 章节再回填；否则以本文件为准（同 B1-7/B2-1/B3-1 先例）。

2. **seed 当前不改变像素（关键边界，须在 PR 标注）**：`Brush::strokeTo` 的 dab 位置抖动 `offset_by_random` 仅在 `OffsetByRandom>0` 时消耗 `nextGauss`，而引擎默认笔刷来自 `createBrush(BrushParams{})` → `OffsetByRandom=0`；`random_input` 虽每 dab 消耗一次 `nextUniform` 但**返回值被丢弃**。因此「同 seed 两次一致」成立且可测，但「不同 seed 产出不同像素」**不可断言**（当前会失败）。B5-3 只把「同 seed 像素级一致」作为验收；「不同 seed 区分」已由 B1-7 `test_determinism` 在 RNG 序列层覆盖。待后续 `.myb`/`dgcCreateBrush` 能设 `offset_by_random>0` 时再补「不同 seed 不同像素」端到端断言。**备选**：若审方坚持 seed 必须影响像素，则需在 B5-3 引入「能设置非零 offset_by_random 的笔刷」——但这触及 `dgcCreateBrush`/`dgcSetBrush`（当前 `NOT_IMPLEMENTED`），属越权，**不自行选，标人工裁决**。

3. **golden PNG 跨机浮点差异（§4.0.3 明示）**：lavapipe compute 用 float32，**同后端同驱动可复现**，跨机/跨驱动允许 ±1 LSB。golden byte-exact diff 只在生成它的同一 dev 机/驱动上必然通过；换机 CI 可能不匹配。**缓解**：①主验收「两次运行逐字节一致」是自洽的、机无关（同机同驱动）；②提交的 golden 仅作同机回归基线，跨机不匹配时走 `regenerate_golden.sh` 重建，不回退测试；③若 CI 需要跨机稳定，可加 `DGCPAIN_GOLDEN_TOLERANCE` 退化到每通道 ±1 LSB 比较（默认 byte-exact）。

4. **LSan 下 Vulkan loader 噪声**：`-DDGCPAIN_SANITIZE=ON` 下离屏段走 lavapipe，Vulkan loader/驱动分配可能在 LSan 误报（B2-1/B3-1 已在同机验证可零报告，但不保证所有环境）。**缓解**：sanitize 构建下若遇 loader 误报，`test_determinism`/`test_cli` 的离屏段沿用「SKIP 离屏、保留机制段」口径，泄漏验证以 `test_ownership_loop`（Null 后端纯 CPU）为准，PR 标注。

5. **first-point t_us=0 细节**：`dgcBeginStroke` 提交 t_us=0，首个 `dgcStrokeTo` 的 `FixedTimeStepper.next()` 也返回 0，故首段 `dtime=0` → 首点可能不产 dab。这是 B1-7/B3-1 既有行为（确定性不因此破坏），B5-3 **不改**；规范脚本用 3 点保证后续段有 dab。若审方在意首段 dab，属 B3-1/B1-7 语义问题，不在本任务。

6. **测试卫生**：所有临时 PNG 统一写 `/tmp/b5_3_*.png`，结束 `::remove` 清理，不在 worktree 根落 `result.png`（同 `test_cli` 卫生口径）。golden fixture 是**有意提交**的 `tests/fixtures/` 下文件，非临时物。
